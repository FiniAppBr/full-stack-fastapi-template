Restaurant AI Test Plan - Dynamic Schema Validation
====================================================

OBJECTIVE:
----------
Validate that our system can handle 10 different restaurant configurations with:
- Custom response schemas (dynamic action fields)
- Multi-turn response breaking
- Media triggers (images, PDFs, videos)
- Different personalities and knowledge bases

Execute 100-200 actual API calls with real token tracking.


PREREQUISITES (Step 1 - Backend Changes):
------------------------------------------

1. Dynamic Schema Support:
   - Agent model needs `response_schema` JSON field
   - Workflow builds Pydantic model dynamically from schema
   - Example schema:
     {
       "order_type": ["dine_in", "delivery", "pickup", "inquiry"],
       "upsell_opportunity": ["yes", "no", "already_maxed"],
       "dietary_restrictions": ["none", "vegetarian", "vegan", "gluten_free", "allergies"]
     }

2. Multi-turn Configuration:
   - Add to agent config:
     {
       "multi_turn": {
         "enabled": true,
         "style": "natural",  // natural | rapid | formal
         "max_splits": 3
       }
     }
   - Workflow splits long responses into 2-3 sequential messages
   - Returns array of messages instead of single string

3. Media Rules:
   - Add to agent config:
     {
       "media_rules": {
         "send_menu_on": ["menu_request", "pricing_question"],
         "send_photos_on": ["dish_question"],
         "send_map_on": ["location_question"]
       }
     }
   - Workflow detects triggers and returns media stubs:
     {
       "messages": ["Here's our menu!", "Anything catch your eye?"],
       "media": [{"type": "pdf", "path": "menu.pdf"}]
     }

EXECUTION PLAN (Step 3):
-------------------------

Phase 1: Setup
--------------
1. Create test agent configs in database (or JSON files)
2. Verify backend accepts dynamic schemas
3. Test workflow with one config manually

Phase 2: Initial Messages
--------------------------
Generate 10 unique customer personas:
1. Hungry college student (late night)
2. Business professional (lunch meeting)
3. Health-conscious mom (family dinner)
4. First-time vegan explorer
5. Sushi enthusiast (specific order)
6. BBQ party planner (20 people)
7. Anniversary couple (romantic)
8. Gym-goer (macro tracking)
9. Broke student (budget hunt)
10. Thai food newbie (needs guidance)

Send initial message to each restaurant → Track response

Phase 3: Conversation Loop
---------------------------
For each conversation (until natural conclusion or 20 turns):
1. Read AI response + structured output
2. Generate contextual user reply based on:
   - Previous messages
   - User persona
   - Natural conversation flow
3. Send message → Track tokens/timing
4. Repeat

Phase 4: Analysis
-----------------
Aggregate metrics:
- Total tokens per conversation
- Average tokens per turn
- Multi-turn effectiveness (feels natural?)
- Structured output accuracy (fields populated correctly?)
- Media trigger appropriateness (sent at right times?)
- Conversation quality (stays in character, uses knowledge)
- Cost projection at scale


METRICS TO TRACK:
-----------------
Per conversation:
- Turn count
- Total input tokens
- Total output tokens
- Total cost (estimated)
- Structured output accuracy (% fields correct)
- Media triggers (count + appropriateness)
- Multi-turn splits (count + naturalness score)
- Knowledge usage (chunks retrieved)
- Conversation outcome (order placed | inquiry answered | escalated)

Aggregate:
- Average tokens per turn (by restaurant type)
- Cost per conversation (by personality/complexity)
- Multi-turn vs single impact on tokens
- Response quality scores
- Feasibility assessment
