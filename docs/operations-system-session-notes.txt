WHAT WAS IMPLEMENTED
================================================================================

1. BACKEND CHANGES
------------------

A) Entity Capability Filter (backend/app/api/routes/entities.py)
   - Added ?capability=X query parameter to GET /api/v1/entities
   - Filters entities by capability: bookable, schedulable, stockable
   - Uses PostgreSQL JSONB @> operator for efficient filtering

B) Operations API Routes (backend/app/api/routes/operations.py)
   New endpoints under /api/v1/operations:

   Entity Links (service-professional relationships):
   - GET    /entity-links                 - List links (filter by source/target/type)
   - POST   /entity-links                 - Create link
   - DELETE /entity-links/{id}            - Delete link

   Booking Configs (service settings):
   - GET    /booking-configs              - List configs (filter by entity_id)
   - GET    /booking-configs/{id}         - Get config
   - POST   /booking-configs              - Create config
   - PATCH  /booking-configs/{id}         - Update config
   - DELETE /booking-configs/{id}         - Delete config

   Inventory (stock management):
   - GET    /inventory                    - List inventory (filter by entity_id, low_stock)
   - GET    /inventory/{id}               - Get inventory
   - POST   /inventory                    - Create inventory
   - PATCH  /inventory/{id}               - Update inventory (auto-sets last_restocked_at)
   - DELETE /inventory/{id}               - Delete inventory

   Combined Views (for frontend):
   - GET    /services                     - Services with booking_config and providers
   - GET    /professionals                - Professionals with linked services
   - GET    /products                     - Products with inventory (filter: low_stock_only)

C) Auto-Create Operational Records (backend/app/api/routes/entities.py)
   - When entity is created with capabilities, auto-creates:
     * BookingConfig for "bookable" capability
     * Inventory for "stockable" capability
   - Same logic on entity update when new capabilities are added

D) Scheduling API Fix (backend/app/api/routes/scheduling.py)
   - POST /api/v1/scheduling/schedules now accepts entity_id (not just professional_id)
   - GET  /api/v1/scheduling/schedules now filters by entity_id OR professional_id
   - Backwards compatible with existing professional_id usage

   - Edit dialog with:

================================================================================
SAMPLE API CALLS FOR TESTING
================================================================================

# Create a bookable entity
curl -X POST http://localhost:5460/api/v1/entities \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Consulta Inicial",
    "category": "products",
    "capabilities": ["bookable"],
    "data": {"price": 150, "description": "Consulta de 1 hora"}
  }'

# Create a schedulable entity
curl -X POST http://localhost:5460/api/v1/entities \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Dr. João Silva",
    "category": "people",
    "capabilities": ["schedulable"],
    "data": {"role": "Médico", "expertise": "Clínico Geral"}
  }'

# Create a stockable entity
curl -X POST http://localhost:5460/api/v1/entities \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Vitamina C 1000mg",
    "category": "products",
    "capabilities": ["stockable"],
    "data": {"price": 45.90, "sku": "VIT-C-1000"}
  }'

# Link service to professional
curl -X POST http://localhost:5460/api/v1/operations/entity-links \
  -H "Content-Type: application/json" \
  -d '{
    "source_entity_id": 1,
    "target_entity_id": 2,
    "relationship_type": "provides"
  }'

# Add schedule for professional
curl -X POST http://localhost:5460/api/v1/scheduling/schedules \
  -H "Content-Type: application/json" \
  -d '{
    "entity_id": 2,
    "day_of_week": 0,
    "start_time": "09:00",
    "end_time": "18:00",
    "slot_duration_minutes": 60,
    "break_between_minutes": 15
  }'

# Add day off exception
curl -X POST http://localhost:5460/api/v1/scheduling/schedules \
  -H "Content-Type: application/json" \
  -d '{
    "entity_id": 2,
    "specific_date": "2025-12-25",
    "start_time": "00:00",
    "end_time": "00:00",
    "is_available": false,
    "notes": "Natal"
  }'
