"Critical Evaluation" - What If We Had To Choose?

This document honestly evaluates V3 by answering two questions:
1. If we had to cut features, what stays and what goes?

## THE BRUTAL HONESTY EXERCISE

We designed a Lamborghini. But do users need a Lamborghini to get to work?
Let's rank every feature by actual impact vs complexity.


### TIER 0: ABSOLUTE CORE (Cannot ship without these)

**1. Agent Node + Basic Personality** ⭐⭐⭐
   - Why: Defines WHO the agent is
   - Complexity: Low
   - Impact: Critical
   - Keep: YES, fundamental

**2. Stage Nodes (Regular)** ⭐⭐⭐
   - Why: The entire concept depends on stages
   - Complexity: Medium
   - Impact: Critical
   - Keep: YES, fundamental

**3. Knowledge Nodes (Document/Custom Instructions)** ⭐⭐⭐
   - Why: Agent needs to know SOMETHING
   - Complexity: Medium (RAG implementation)
   - Impact: Critical
   - Keep: YES, but START with documents only, add APIs later

**4. Data Collection Goals** ⭐⭐⭐
   - Why: Business needs to collect info
   - Complexity: Medium
   - Impact: Critical
   - Keep: YES, core value proposition

**5. Basic Transitions (Agent Decides + All Data Collected)** ⭐⭐⭐
   - Why: Need to move between stages
   - Complexity: Low-Medium
   - Impact: Critical
   - Keep: YES, but only 2 transition types initially


### TIER 1: HIGH VALUE (MVP should have these)

**6. Variables System** ⭐⭐⭐
   - Why: Makes everything else work
   - Complexity: Medium
   - Impact: Very High
   - Keep: YES, enabler for everything

**7. Response Behavior (Message Bundling + Fragmentation)** ⭐⭐⭐
   - Why: Differentiator - makes agent feel human
   - Complexity: Low (10s buffer) to Medium (fragmentation)
   - Impact: High (user experience quality)
   - Keep: YES, but maybe just buffer initially

**8. Action Nodes (Basic: Create Order, Send Email, Handoff to Human)** ⭐⭐⭐
   - Why: Agent must DO things, not just talk
   - Complexity: Medium (depends on integrations)
   - Impact: High (business value)
   - Keep: YES, but start with 3-4 actions only

**9. Goal Tracking & Basic Analytics** ⭐⭐
   - Why: Businesses need to measure success
   - Complexity: Medium
   - Impact: High (proves ROI)
   - Keep: YES, simplified version

**10. Testing Mode** ⭐⭐⭐
   - Why: Can't ship without ability to test
   - Complexity: Medium
   - Impact: Critical (dev experience)
   - Keep: YES, but basic version


### TIER 2: NICE TO HAVE (Add after MVP validation)

**11. Live Data Integration (API nodes)** ⭐⭐⭐
   - Why: Makes agent truly intelligent
   - Complexity: HIGH (auth, mapping, error handling)
   - Impact: Very High
   - Decision: DEFER to Phase 2
   - Reality check: Most businesses will use static docs first anyway

**12. Sentiment-Based Adaptation** ⭐⭐
   - Why: Quality improvement
   - Complexity: Medium (sentiment analysis)
   - Impact: Medium (nice but not essential)
   - Decision: DEFER to Phase 2
   - Reality check: Personality already covers tone

**13. Context Rules (Time, Channel, Customer)** ⭐⭐
   - Why: Personalization
   - Complexity: Medium
   - Impact: Medium
   - Decision: DEFER to Phase 2
   - Reality check: Can handle 80% of cases without this

**14. Intent to Send Nodes** ⭐⭐
   - Why: Proactive media sharing
   - Complexity: Low
   - Impact: Medium
   - Decision: MAYBE include as "Send Image" action
   - Reality check: Could be simplified to action node

**15. Conditional Stages** ⭐⭐
   - Why: Personalization per customer type
   - Complexity: Medium
   - Impact: Medium
   - Decision: DEFER to Phase 2
   - Reality check: Can create separate flows for VIP vs Regular


### TIER 3: ADVANCED (Only if we scale successfully)

**16. Multi-Agent Orchestration** ⭐⭐⭐ (High value BUT...)
   - Why: Huge differentiator
   - Complexity: VERY HIGH (orchestration, handoffs, context passing)
   - Impact: Very High (enterprise feature)
   - Decision: PHASE 3 or later
   - Reality check: Users need to master ONE agent first

**17. Sub-flows / Reusable Components** ⭐⭐⭐
   - Why: DRY principle, maintainability
   - Complexity: HIGH (recursive structures, variable passing)
   - Impact: High (for power users)
   - Decision: PHASE 3
   - Reality check: Copy-paste stages works for MVP

**18. Human-in-the-Loop (Hybrid mode)** ⭐⭐⭐
   - Why: Novel approach, best of both worlds
   - Complexity: HIGH (real-time notifications, waiting states, timeouts)
   - Impact: High (but niche use case)
   - Decision: PHASE 3
   - Reality check: "Handoff to Human" covers 90% of need

**19. Learning & Optimization Engine** ⭐⭐⭐
   - Why: Agent improves over time
   - Complexity: VERY HIGH (ML patterns, training UI, safe auto-optimization)
   - Impact: Very High (long-term stickiness)
   - Decision: PHASE 4
   - Reality check: Need data from thousands of conversations first

**20. A/B Testing** ⭐⭐
   - Why: Scientific optimization
   - Complexity: HIGH (traffic splitting, stats significance)
   - Impact: Medium (for mature users)
   - Decision: PHASE 4+
   - Reality check: Premature optimization


### TIER 4: CUT (Honestly, maybe never)

**21. Training Dashboard (Manual training)** ⭐
   - Why: Improve agent responses
   - Complexity: HIGH (annotation UI, feedback loop)
   - Impact: Low-Medium (time-intensive for users)
   - Decision: CUT or very late
   - Reality check: Users won't have time for this. Auto-learning or nothing.

**22. Memory Node (mem0 integration)** ⭐⭐
   - Why: Remember customer across sessions
   - Complexity: HIGH (privacy, storage, retrieval)
   - Impact: Medium
   - Decision: DEFER to Phase 3+
   - Reality check: Variables within session cover 80% of use cases

**23. Version Control** ⭐
   - Why: Track changes, restore
   - Complexity: Medium
   - Impact: Low (standard feature, not differentiator)
   - Decision: DEFER to Phase 3
   - Reality check: Just save copies for now

**24. Collaboration (Multi-user editing)** ⭐
   - Why: Team feature
   - Complexity: VERY HIGH (real-time sync, conflicts)
   - Impact: Low (most businesses = 1 person configures)
   - Decision: DEFER indefinitely
   - Reality check: Share accounts works fine initially

## REALISTIC MVP FEATURE SET (Ship This First)

**CORE NODES:**
  - Agent Node (with basic personality settings)
  - Stage Node (regular only)
  - Knowledge Node (documents + custom instructions only)
  - Data Collection Goal (with necessity levels)
  - 3 Action Nodes: Create Order, Send Email, Handoff to Human
  - Transition Arrows (2 types: Agent Decides, All Data Collected)

**SUPPORTING FEATURES:**
  - Variables System (collected + custom only, no computed/memory yet)
  - Response Behavior (10s buffer + optional fragmentation)
  - Goal Tracking (primary goal only)
  - Basic Analytics (goal achievement %, avg time, stage flow)
  - Testing Mode (chat simulator + basic debug)

**WHAT'S MISSING:**
  - No live APIs (Phase 2)
  - No sentiment adaptation (Phase 2)
  - No context rules (Phase 2)
  - No conditional stages (Phase 2)
  - No multi-agent (Phase 3)
  - No sub-flows (Phase 3)
  - No human-in-the-loop hybrid (Phase 3)
  - No learning engine (Phase 4)
  - No memory/mem0 (Phase 3+)

**CAN WE STILL DELIVER VALUE?**

YES. This MVP lets businesses:
  ✅ Create conversational AI agents with personality
  ✅ Design stage-based flows (our core differentiator)
  ✅ Collect customer data naturally
  ✅ Connect to business systems (orders, emails)
  ✅ Measure success (goal achievement)
  ✅ Feel human (message bundling, fragmentation)
  ✅ Handoff to humans when needed

This is ALREADY better than:
  - Chatfuel/Manychat (rigid button flows)
  - Pure GPT wrapper (no structure, no control)
  - Most "AI chatbot builders" (no stage concept)

## THE HONEST ASSESSMENT

**What we got RIGHT in V3:**
  ✅ Stage-based conversation design (unique, valuable)
  ✅ Visual flowchart as source of truth (UX innovation)
  ✅ Variables as first-class (enables everything)
  ✅ Humanization (buffer, fragmentation) (differentiator)
  ✅ Goal-oriented (business outcomes, not just chat)

**What we OVER-ENGINEERED:**
  ⚠️ Multi-agent orchestration (too complex for MVP)
  ⚠️ Sub-flows (premature abstraction)
  ⚠️ Human-in-the-loop hybrid (niche, complex)
  ⚠️ Learning engine (need data first)
  ⚠️ Manual training dashboard (users won't do it)
  ⚠️ A/B testing (premature optimization)
  ⚠️ Version control (nice-to-have)
  ⚠️ Collaboration features (team feature for later)

**What we might be UNDER-ESTIMATING:**
  ⚠️ Complexity of RAG (knowledge retrieval quality)
  ⚠️ Transition condition evaluation (when is "agent decides" good enough?)
  ⚠️ Testing at scale (simulating 100s of conversation paths)
  ⚠️ Integration hell (every Action node = API integration work)

## THE HARD QUESTION

Is the "unified flowchart for everything" the RIGHT model?
Or are we forcing a visual paradigm where it doesn't fit?

Let's explore 3 alternative designs:


────────────────────────────────────────────────────────────────────
ALTERNATIVE 1: HYBRID - Tabs + Flowchart
────────────────────────────────────────────────────────────────────

**Concept:**
  - Global settings in TABS (like originally planned)
  - Flowchart is JUST for conversation flow (stages + transitions)
  - Knowledge, personality, actions configured separately

**Layout:**

Tabs: [Personality] [Knowledge] [Actions] [Conversation Flow] [Analytics]

**Personality Tab:**
  Simple form with tone, language, do's/don'ts
  No nodes, no connections

**Knowledge Tab:**
  List of documents + custom instructions
  Toggle: "Available in all stages" or "Select stages"

**Actions Tab:**
  List of available actions (Schedule Appointment, Create Order, etc.)
  Configure each action once
  In flowchart, just reference by name

**Conversation Flow Tab:**
  Simplified flowchart:
    - Only Stage nodes
    - Only Transition arrows
  Inside each stage:
    - Which knowledge? (select from list)
    - Which actions? (select from list)
    - What data to collect? (add goals)
    - Transition conditions

**Pros:**
  ✅ Cleaner separation of concerns
  ✅ Less visual clutter on canvas
  ✅ Easier for beginners (familiar tab interface)
  ✅ Configure once, use everywhere (actions, knowledge)
  ✅ No confusing "global vs stage-specific" on same canvas

**Cons:**
  ❌ Lose "flowchart is source of truth" purity
  ❌ Settings scattered across tabs (less coherent mental model)
  ❌ Can't see at-a-glance what knowledge is active where
  ❌ More clicking between tabs

**Verdict:**
  This is MORE intuitive for most users.
  Less elegant, but more pragmatic.
  **Consider this seriously.**


────────────────────────────────────────────────────────────────────
ALTERNATIVE 2: PROMPT-BASED (Minimal Visual)
────────────────────────────────────────────────────────────────────

**Concept:**
  What if we embrace AI instead of fighting it?
  Users describe their agent in natural language.
  AI generates the flowchart.
  Users tweak visually.

**Flow:**

1. **Setup Wizard (Conversational):**
   AI: "What does your business do?"
   User: "We sell handmade jewelry online"

   AI: "What should your agent help customers with?"
   User: "Answer product questions, take orders, handle complaints"

   AI: "What information do you need from customers?"
   User: "Name, email, shipping address, product preferences"

   AI: "What's your brand personality?"
   User: "Friendly, artistic, personal touch"

   [AI generates flowchart automatically]

2. **Visual Review & Edit:**
   - AI-generated flowchart appears
   - User can edit stages, add/remove transitions
   - Visual tweaks, not building from scratch

3. **Refinement:**
   - Test mode
   - User gives feedback: "Agent is too verbose in greeting"
   - AI adjusts

**Pros:**
  ✅ Zero learning curve (just describe your business)
  ✅ Fast time-to-value (agent ready in 5 minutes)
  ✅ AI does the hard work (deciding stages, transitions)
  ✅ Non-technical users can succeed
  ✅ Can still have visual editor for power users

**Cons:**
  ❌ Requires very good AI understanding of business domains
  ❌ Less control (black box generation)
  ❌ Users might not trust AI-generated flow
  ❌ Hard to implement well (AI must make good architecture decisions)

**Verdict:**
  Intriguing for onboarding, but risky as sole method.
  **Could be "wizard mode" option alongside manual builder.**


────────────────────────────────────────────────────────────────────
ALTERNATIVE 3: CONVERSATION SCRIPT (Linear with Branches)
────────────────────────────────────────────────────────────────────

**Concept:**
  Most conversations are more LINEAR than we think.
  What if we model it as a SCRIPT with branch points, not a complex graph?

**Interface:**

Left side: Outline view (like a script)
Right side: Preview (chat simulation)

**Outline Structure:**

```
1. GREETING
   - Agent says: "Hi! How can I help?"
   - Collect: customer_name (optional)
   - Branch on: customer_intent

2a. IF intent = order_question
    → ORDER SUPPORT
    - Agent knows: Return Policy, Shipping FAQ
    - Collect: order_number (required)
    - Agent action: Look up order
    - Branch: resolved? → 5. WRAP UP
    - Branch: not resolved? → 4. ESCALATE

2b. IF intent = product_question
    → PRODUCT HELP
    - Agent knows: Product Catalog
    - Collect: product_interest
    - Agent action: Recommend products
    - Branch: wants to buy? → 3. CHECKOUT
    - Branch: still browsing? → 5. WRAP UP

2c. IF intent = complaint
    → COMPLAINT HANDLING
    - Agent knows: Refund Policy
    - Agent personality override: extra empathetic
    - Branch: angry? → 4. ESCALATE
    - Branch: calm? → resolve and → 5. WRAP UP

3. CHECKOUT
   - Collect: shipping_address (required)
   - Collect: payment_info (required)
   - Agent action: Create Order
   - → 5. WRAP UP

4. ESCALATE
   - Agent action: Handoff to Human
   - END

5. WRAP UP
   - Agent says: "Anything else I can help with?"
   - Branch: yes → back to 2
   - Branch: no → END
```

**Visual Representation:**
  Collapsible tree view (like a code editor)
  Each section expands to show details
  Branch arrows connect sections

**Pros:**
  ✅ Matches how people think (sequential with exceptions)
  ✅ Easy to scan (outline format)
  ✅ Less intimidating than graph (no complex flowchart)
  ✅ Natural branching (IF-THEN feels intuitive)
  ✅ Can still have visual mode (auto-generate from outline)

**Cons:**
  ❌ Complex flows get messy (deeply nested branches)
  ❌ Hard to see "big picture" (vs flowchart)
  ❌ Loop-backs can be confusing (how to represent?)

**Verdict:**
  Interesting middle ground.
  **Could work for simple flows, but scales poorly for complex ones.**


────────────────────────────────────────────────────────────────────
ALTERNATIVE 4: STATE MACHINE TABLE (Power User)
────────────────────────────────────────────────────────────────────

**Concept:**
  For developers/technical users, a table is clearest.
  Each row = a state (stage).
  Columns = properties.

**Interface:**

Spreadsheet-like table:

| Stage Name      | Knowledge        | Collects         | Actions          | Transitions To           |
|-----------------|------------------|------------------|------------------|--------------------------|
| Greeting        | Brand Voice      | name (optional)  | -                | Discovery (agent decides)|
| Discovery       | FAQ, Products    | intent (required)| -                | Order Support (if intent=order) |
|                 |                  |                  |                  | Product Help (if intent=product) |
|                 |                  |                  |                  | Complaint (if intent=complaint) |
| Order Support   | Return Policy    | order_num (req)  | Lookup Order     | Resolution (if resolved) |
|                 | Shipping FAQ     |                  |                  | Escalate (if stuck)      |
| Product Help    | Product Catalog  | product_interest | Recommend        | Checkout (if buying)     |
|                 |                  |                  |                  | Wrap Up (if browsing)    |
| Checkout        | -                | shipping, payment| Create Order     | Wrap Up                  |
| Escalate        | -                | -                | Handoff to Human | END                      |
| Wrap Up         | -                | satisfaction     | -                | Discovery (if more questions) |
|                 |                  |                  |                  | END (if done)            |

Click any cell to edit details.

**Pros:**
  ✅ Maximum information density (see everything at once)
  ✅ Easy to scan and compare
  ✅ Familiar to technical users (CSV-like)
  ✅ Easy to import/export (CSV, Excel)
  ✅ Fast to edit (keyboard navigation)

**Cons:**
  ❌ Overwhelming for non-technical users
  ❌ No visual flow representation
  ❌ Hard to see conversation paths
  ❌ Complex conditions don't fit in table cells

**Verdict:**
  Great for technical users, terrible for most.
  **Could be "advanced view" toggle for power users.**

## REDESIGN EVALUATION

After exploring alternatives, which approach is BEST?


### Option A: Stick with V3 (Unified Flowchart)
**Best for:** Visual thinkers, designers, marketing teams
**Weakness:** Complexity, potential clutter
**Rating:** 8/10 - Great for our target user (business owners who want control)

### Option B: Hybrid (Tabs + Simplified Flowchart)
**Best for:** Broadest audience, most intuitive
**Weakness:** Less elegant, settings in multiple places
**Rating:** 9/10 - Most pragmatic, likely to succeed
**Recommendation:** **SERIOUSLY CONSIDER THIS**

### Option C: AI-Generated (Prompt-based)
**Best for:** Non-technical users, fast setup
**Weakness:** Less control, AI must be very good
**Rating:** 7/10 - Great as onboarding wizard, not sole interface

### Option D: Linear Script (Outline view)
**Best for:** Simple, linear conversations
**Weakness:** Doesn't scale to complex flows
**Rating:** 6/10 - Niche use case

### Option E: State Machine Table
**Best for:** Developers, technical users
**Weakness:** Intimidating for most users
**Rating:** 5/10 - Power user feature only

## RECOMMENDED DESIGN: HYBRID APPROACH (Best of V3 + Tabs)

**Core Insight:**
  - Some things are NATURALLY GLOBAL (personality, available actions)
  - Some things are NATURALLY PER-STAGE (what data to collect, when to transition)
  - Forcing everything on one canvas was elegant but impractical

**New Design:**

┌────────────────────────────────────────────────────────────────┐
│ [← Back]  Sales Agent                              [Save] [Test]│
│                                                                  │
│ Tabs: [🤖 Agent] [📚 Knowledge] [⚡ Actions] [🎯 Flow] [📊 Analytics] │
└────────────────────────────────────────────────────────────────┘


**🤖 AGENT TAB:**
  Simple form (no nodes):
    - Agent name
    - Model (Claude, GPT-4)
    - Personality settings
      - Tone, verbosity, language
      - Do's and Don'ts
    - Response behavior (global defaults)
      - Message bundling (10s buffer?)
      - Fragmentation (2-3 messages?)
      - Typing indicators
    - Memory settings (if enabled)
    - Conversation goal (what's success?)


**📚 KNOWLEDGE TAB:**
  List view (no nodes):
    ┌──────────────────────────────────────┐
    │ [+ Add Knowledge]                    │
    ├──────────────────────────────────────┤
    │ ☑ Return Policy.pdf                  │
    │   Scope: All stages                  │
    │   [Edit] [Delete]                    │
    │                                      │
    │ ☑ Product Catalog                    │
    │   Scope: Discovery, Product Help     │
    │   [Edit] [Delete]                    │
    │                                      │
    │ ☑ Shipping FAQ                       │
    │   Scope: Order Support               │
    │   [Edit] [Delete]                    │
    └──────────────────────────────────────┘

  When creating knowledge:
    - Upload/select source
    - Choose scope: All stages OR Select specific stages


**⚡ ACTIONS TAB:**
  List view (configure once, use in flow):
    ┌──────────────────────────────────────┐
    │ [+ Add Action]                       │
    ├──────────────────────────────────────┤
    │ 📧 Send Welcome Email                │
    │    Trigger: Manual (in flow)         │
    │    [Edit] [Test] [Delete]            │
    │                                      │
    │ 🛒 Create Order                      │
    │    Trigger: Manual (in flow)         │
    │    Integration: Shopify              │
    │    [Edit] [Test] [Delete]            │
    │                                      │
    │ 📞 Handoff to Human                  │
    │    Department: Support Team          │
    │    [Edit] [Delete]                   │
    └──────────────────────────────────────┘


**🎯 FLOW TAB:**
  THIS is the flowchart canvas (simplified):

  ┌─────────────┬──────────────────────────────────┬─────────────┐
  │             │                                  │             │
  │   TOOLBOX   │        CANVAS                    │ PROPERTIES  │
  │             │                                  │             │
  │ ⊕ Stage     │   [Greeting] → [Discovery]       │ Stage:      │
  │ ⊕ End Stage │        ↓            ↓            │ Discovery   │
  │             │   [Order]      [Product]         │             │
  │             │        ↓            ↓            │ Knowledge:  │
  │             │   [Resolve]    [Checkout]        │ • FAQ (all) │
  │             │        ↓            ↓            │ • Products  │
  │             │      [END]        [END]          │             │
  │             │                                  │ Collect:    │
  │             │                                  │ • intent    │
  │             │                                  │             │
  │             │                                  │ Actions:    │
  │             │                                  │ (none)      │
  │             │                                  │             │
  │             │                                  │ Transitions:│
  │             │                                  │ [+ Add]     │
  └─────────────┴──────────────────────────────────┴─────────────┘

  **Stage nodes are simpler:**
    - Name + color
    - List of data goals (with necessity levels)
    - Reference to actions (select from list)
    - Transition rules

  **No nested nodes!**
    - Knowledge is configured in Knowledge tab, referenced here
    - Actions are configured in Actions tab, referenced here
    - Personality is in Agent tab, applies globally

  **Benefits:**
    ✅ Cleaner canvas (just stages + arrows)
    ✅ Configure complex things once (knowledge, actions)
    ✅ Reference by name (less duplication)
    ✅ Easier to see conversation flow
    ✅ No confusion about "global vs stage-specific on canvas"


**📊 ANALYTICS TAB:**
  Same as V3 (goal achievement, stage metrics, optimizations)

## FINAL RECOMMENDATION

**For MVP, use HYBRID approach:**

1. **Agent Tab** - Personality, behavior, goals (simple form)
2. **Knowledge Tab** - Documents, instructions (list, choose scope)
3. **Actions Tab** - Configure actions once (list)
4. **Flow Tab** - Visual flowchart (ONLY stages + transitions)
5. **Analytics Tab** - Metrics

**Why this wins:**
  ✅ Familiar interface (tabs are universal)
  ✅ Cleaner flowchart (just conversation flow)
  ✅ Configure once, reference many (DRY principle)
  ✅ Easier to implement (fewer node types, simpler canvas)
  ✅ Lower learning curve (beginners succeed faster)
  ✅ Still powerful (all features accessible)

**What we learned from V3:**
  - Stage-based design is CORRECT ✓
  - Variables are essential ✓
  - Humanization (buffer, fragmentation) is differentiator ✓
  - Goal tracking is critical ✓
  - "Everything on canvas" is elegant but impractical ✗

**V3 was necessary thought exercise.**
**Hybrid is pragmatic execution.**

## PROGRESSIVE DISCLOSURE STRATEGY

Even with hybrid approach, can still add complexity later:

**Phase 1 (MVP):**
  - 5 tabs (Agent, Knowledge, Actions, Flow, Analytics)
  - Simple forms in each tab
  - Flowchart has only Stage nodes

**Phase 2:**
  - Add "Advanced" toggle in each tab
  - Agent tab: Context rules, sentiment adaptation
  - Knowledge tab: Live API integrations
  - Actions tab: Custom webhooks
  - Flow tab: Conditional stages

**Phase 3:**
  - Multi-agent (new top-level: "Agents" manages multiple flows)
  - Sub-flows (collapsible stages in Flow tab)
  - Human-in-the-loop (special action type)

**Phase 4:**
  - Learning dashboard (new tab)
  - A/B testing (Flow tab feature)


This way, beginners see simple interface.
Power users unlock complexity as needed.

CONCLUSION: THE VERDICT
════════════════════════════════════════════════════════════════════

**Should we proceed with V3 design?**
NO. It's over-engineered for MVP.

**Should we abandon the core concept?**
NO. Stage-based AI conversation design is brilliant and unique.

**What should we build?**
HYBRID approach with tabs + simplified flowchart.

**Why?**
  - Faster to implement
  - Easier for users to learn
  - Still delivers core value (stage-based conversational AI)
  - Can add complexity progressively
  - Higher chance of MVP success

**The core innovation remains:**
  Users design AI conversations through stages with goals,
  not rigid button flows or unstructured prompts.

**The delivery method changes:**
  From "everything is a visual node"
