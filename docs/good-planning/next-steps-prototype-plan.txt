ConnectAI - Next Steps: v0.1 Prototype Plan
=============================================

DECISION: Build a Working Prototype Now
----------------------------------------

The Builder AI + Block List concept is solid and self-validating.
Next step is to build a working prototype to prove it feels right.

Timeline: 1-2 weeks
Goal: See the interface working end-to-end, validate the UX


WHY BUILD PROTOTYPE FIRST (Not extensive validation):
------------------------------------------------------

1. **The Concept is Self-Validating**
   - If technical users prefer chat interface over manual config,
     non-technical users definitely will
   - The value prop is clear and obvious
   - Low risk of building the wrong thing

2. **Working Demo = Better Validation**
   - Showing someone a working prototype is 10x more validating
     than mockups or descriptions
   - Can test with real users once it's working
   - Get actual feedback on the experience

3. **We Already Have the Stack**
   - React + TypeScript ✓
   - FastAPI + Python ✓
   - Material UI ✓
   - Know how to build chat interfaces
   - Know how to build forms/cards
   - This isn't a huge technical leap

4. **Momentum Matters**
   - Team is excited and motivated
   - Strike while the iron is hot
   - Fast feedback loop (will know in 2 weeks if this works)

5. **Low Cost, High Learning**
   - Worst case: spent 2 weeks and learned a lot
   - Best case: validated a game-changing feature
   - Either way, it's worth it


v0.1 PROTOTYPE SCOPE (1-2 weeks)
---------------------------------

Goal: Working split-screen where you can chat with Builder AI,
      it creates blocks, and you can see them update in real-time.


FRONTEND (3-4 days):
--------------------

1. Split-screen layout
   - Left side: Block list (collapsible sections)
   - Right side: Chat interface with file drop zone
   - Responsive (works on desktop, maybe mobile later)

2. Block types (only 3-4 for v0.1):
   - Personality Block (tone, emoji usage, language)
   - Text/Info Block (hours, policies, FAQs)
   - Document Block (upload PDF, show extracted content)
   - Handoff Block (when to escalate to human)

3. Basic chat UI:
   - Message list (Builder AI + User messages)
   - Input box
   - File drop zone
   - "Creating block..." loading states
   - Scroll to bottom on new message

4. Block list UI:
   - Collapsible sections (Knowledge, Behavior, Actions, etc.)
   - Each block is a card
   - Click to expand/edit
   - Can manually add blocks (+ button)
   - Can delete blocks


BACKEND (3-4 days):
-------------------

1. Builder AI endpoint:
   - POST /api/v1/builder/chat
   - Takes: agent_id, user_message, (optional) file
   - Returns: AI response, block_commands (create/update/delete)
   - Stores conversation history

2. Simple Builder AI (v0.1):
   DON'T build full LLM agent yet for v0.1

   Option A (Fastest):
   - Hardcoded conversation flow
   - Scripted questions: "Tell me about your business" →
     "What tone?" → "Upload docs"
   - Simple pattern matching for answers
   - Deterministic block creation

   Option B (Smarter):
   - Use GPT-4 with SIMPLE prompt
   - Function calling for block creation
   - Keep prompt minimal for v0.1

   Recommendation: Start with Option A, upgrade to B if time permits

3. Block CRUD API:
   - POST /api/v1/agents/{agent_id}/blocks (create)
   - GET /api/v1/agents/{agent_id}/blocks (list)
   - PATCH /api/v1/agents/{agent_id}/blocks/{block_id} (update)
   - DELETE /api/v1/agents/{agent_id}/blocks/{block_id} (delete)

4. File upload + basic parsing:
   - Accept PDF upload
   - Extract text using PyPDF2 or similar
   - Store extracted text in DocumentBlock
   - Show preview in UI
   - Don't worry about SMART extraction yet (v0.1 just shows raw text)

5. Data models:
   - Agent (belongs to User)
   - Block (polymorphic: PersonalityBlock, TextBlock, DocumentBlock, etc.)
   - BuilderConversation (chat history between user and Builder AI)

BACKEND ARCHITECTURE (Think About During Build):
-------------------------------------------------

Data Model:
-----------
User
  └── Agents (can have multiple agents)
       ├── Blocks (configuration)
       │    ├── PersonalityBlock
       │    ├── KnowledgeBlock (text, documents)
       │    ├── ActionBlock (appointments, forms, payments)
       │    ├── IntegrationBlock (calendar, email, etc.)
       │    └── RuleBlock (conditions, handoffs)
       ├── BuilderConversation (chat history with Builder AI)
       └── AgentConversations (customer interactions)

Two AI Systems:
---------------
1. Builder AI (helps user configure)
   - Access to: Block creation tools, file parsing, integrations
   - Goal: Set up agent correctly in <10 minutes
   - Context: Business type, previous blocks, what's missing

2. Customer Agent (talks to end customers)
   - Access to: Configured blocks, knowledge base, actions (booking, payment)
   - Goal: Help customers according to configuration
   - Context: Customer data, conversation history, available actions

Key Technical Decisions:
-------------------------
For v0.1, keep it simple. These can be refined later:

- Block storage: JSON in PostgreSQL (simple, flexible)
- Knowledge base: Simple text search for v0.1, vector DB later
- Builder AI: Stateful conversation (store context in DB)
- File processing: Sync for v0.1 (small files), async later
- Agent runtime: Generate responses on-demand (not pre-scripted)

Don't over-architect yet. Build v0.1, see what works, then architect properly.

RISKS & MITIGATION:
-------------------

Risk 1: "Builder AI conversation is awkward or confusing"
→ Start simple (hardcoded flow), iterate based on testing
→ Can always fall back to manual block adding

Risk 2: "Split-screen is cluttered on small screens"
→ Make it tabs on mobile (Chat tab | Configure tab)
→ Focus on desktop first for v0.1

Risk 3: "File parsing doesn't work well"
→ Start with simple text extraction
→ Show user what was extracted, let them edit
→ Add smart parsing in v0.2

Risk 4: "Takes longer than 2 weeks"
→ Cut scope aggressively (fewer block types, simpler AI)
→ Goal is working demo, not production-ready
→ Ugly but functional is fine for v0.1

Risk 5: "Users don't like conversational interface"
→ That's what we're testing!
→ Easy to pivot back to pure block list
→ Or offer both options


DEVELOPMENT APPROACH:

3. Then add sophistication (better AI, more blocks, polish)
