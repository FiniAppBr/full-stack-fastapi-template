REFRAMING THE PROBLEM:
----------------------

We have TWO distinct AI systems to build:

1. **Builder AI** - Helps user configure their agent (chat interface)
2. **Customer Agent** - Handles customer conversations (the actual bot)

Each has different challenges and requirements.


CHALLENGE 1: BUILDER AI
========================

What it needs to do:
- Chat with business owner
- Ask clarifying questions
- Parse uploaded files (PDFs, spreadsheets, images)
- Create/update blocks based on conversation
- Validate configuration is complete
- Suggest improvements

PROBLEMS WITH NAIVE APPROACH:
------------------------------

1. **Token cost for long conversations**
   - Builder conversation might be 50+ messages
   - Each call sends full history
   - Expensive with GPT-4

2. **File parsing intelligence**
   - Need to extract structure from PDFs/docs
   - Tables, lists, prices, names, etc.
   - GPT-4 Vision can help but costly

3. **Context management**
   - What blocks already exist?
   - What's been discussed?
   - What's missing?
   - Needs to track state across conversation

4. **Multi-step reasoning**
   - "User said they're a restaurant → need menu, hours, reservations"
   - "User uploaded pricing → extract, validate, create block"
   - Multiple LLM calls per user message


STATE-OF-THE-ART SOLUTIONS FOR BUILDER AI:
-------------------------------------------

SOLUTION 1: Multi-Model Strategy (Cost Optimization)
-----------------------------------------------------

Don't use GPT-4 for everything. Use cheaper models for simple tasks.

**Tier 1: Routing/Classification (ultra cheap, fast)**
- Gemini Flash 2.0 (free tier, <1s latency)
- Claude Haiku
- Use for: Intent detection, routing, simple yes/no

**Tier 2: Reasoning (moderate cost)**
- GPT-4o-mini
- Claude Sonnet
- Use for: Generating responses, asking questions

**Tier 3: Complex Reasoning (expensive, use sparingly)**
- GPT-4o
- Claude Opus
- Use for: File parsing, complex validation

Example flow:
```
User message arrives
    ↓
[Gemini Flash] Classify: "user_uploading_file" or "user_answering_question"?
    ↓
If file:
    [GPT-4 Vision] Parse file → extract structure
    ↓
[GPT-4o-mini] Generate response: "I found X items, creating blocks..."
    ↓
Done
```

**Token savings: 70-80%**
**Latency: Better (Gemini Flash is faster than GPT-4)**

**MANIS INSIGHT:** Test architecture by toggling between weak/strong models.
If weak model → strong model gives big improvement, architecture is future-proof.


SOLUTION 2: LangGraph for Builder AI (RECOMMENDED)
---------------------------------------------------

Builder AI is perfect for LangGraph because it's a WORKFLOW with clear steps.

**Build Builder AI as a state machine:**

```python
from langgraph.graph import StateGraph

class BuilderState(TypedDict):
    business_type: str
    business_description: str
    blocks: List[Block]
    current_step: str
    pending_questions: List[str]
    files_uploaded: List[FileMetadata]

# Define workflow
workflow = StateGraph(BuilderState)

# Nodes (steps)
workflow.add_node("greet", greet_user)
workflow.add_node("identify_business", ask_about_business)
workflow.add_node("process_file", parse_uploaded_file)  # Agent-as-tool
workflow.add_node("create_blocks", generate_blocks_from_info)
workflow.add_node("configure_personality", set_tone_and_style)
workflow.add_node("setup_integrations", connect_calendar_etc)
workflow.add_node("validate", check_completeness)

# Define flow
workflow.set_entry_point("greet")
workflow.add_edge("greet", "identify_business")
workflow.add_conditional_edges(
    "identify_business",
    route_next_step,
    {
        "need_more_info": "identify_business",
        "file_uploaded": "process_file",
        "configure_tone": "configure_personality",
        "setup_calendar": "setup_integrations"
    }
)

app = workflow.compile()
```

**Benefits:**
- Clear structure (easier to debug and improve)
- State is explicit (know exactly what's been done)
- Can pause/resume (user can come back later)
- Each node can use different model (cost optimization)
- Observability (see which node failed)

**This solves context management for Builder AI.**


SOLUTION 3: Agent-as-Tool Pattern (MANIS INSIGHT)
--------------------------------------------------

Don't make Builder AI do everything. Delegate to specialist sub-agents.

**When user uploads PDF:**
```python
# Builder AI spawns specialist agent
file_parser = AgentAsTool(
    name="file_parser",
    model="gpt-4-vision",
    output_schema=ParsedDocument,  # Enforce structured output
    tools=[extract_table, extract_text, extract_images]
)

parsed_data = file_parser.process(uploaded_file)
# Returns: ParsedDocument(type="pricing_table", items=[...], confidence=0.9)

# Builder AI uses parsed data to create blocks
builder_ai.create_block(parsed_data)
```

**KEY: Main agent defines output schema for sub-agent (constraint decoding)**

**MANIS INSIGHT:** Use agent-as-tool for:
- Complex searches
- File parsing
- Data processing
- Any workflow that needs structured output

**Tools that help:**
- **LlamaIndex** - Document parsing
- **Unstructured.io** - Extract tables, text, images
- **DocAI / AWS Textract** - OCR + structure extraction


SOLUTION 4: Structured Outputs for Reliability
-----------------------------------------------

**MANIS INSIGHT:** Use schemas as contracts everywhere.

**For summarization:**
```python
class ConversationSummary(BaseModel):
    business_type: str
    blocks_created: List[str]
    blocks_missing: List[str]
    files_uploaded: List[str]
    current_goal: str
    user_preferences: Dict[str, Any]

# Don't use free-form summarization
summary = builder_ai.summarize(
    conversation=messages,
    response_model=ConversationSummary  # Structured!
)
```

**For sub-agent communication:**
```python
# Main agent defines schema
class SearchResult(BaseModel):
    findings: List[str]
    sources: List[str]
    confidence: float

# Sub-agent must conform
search_agent = AgentAsTool(
    output_schema=SearchResult,  # Enforced via constraint decoding
    tools=[search_web, search_docs]
)
```

**Benefits:**
- No missing fields
- Type-safe
- Easy to iterate on
- Prevents free-form chaos

CHALLENGE 2: CUSTOMER AGENT
============================

What it needs to do:
- Understand customer intent
- Search knowledge blocks for relevant info
- Take actions (book appointments, check prices, escalate)
- Maintain conversation context
- Respect personality constraints
- Handle 100s of concurrent conversations
- Stay under token/cost budget

PROBLEMS WITH NAIVE APPROACH:
------------------------------

1. **Token cost at scale**
   - 1000 conversations/day × 10 messages × $0.03 = $300/day per business

2. **Context window limits**
   - Need to remember past conversations
   - Can't send all past messages (expensive, hits limits)

3. **Latency requirements**
   - Customers expect <2 second response

4. **Tool overload**
   - Too many tools (>30) causes confusion
   - AI calls wrong tools or non-existent ones

5. **Context explosion**
   - Agents call tools freely
   - Tool messages accumulate
   - Context grows unbounded


SOLUTION 1: LAYERED ACTION SPACE (MANIS BREAKTHROUGH)
------------------------------------------------------

**THE PROBLEM:** Function calling breaks KV cache, limits grow with tools.

**THE SOLUTION:** Three-tier system

**LAYER 1: Atomic Function Calling (10-20 tools MAX)**
- read_file, write_file, execute_shell, search_web, browser_action
- Schema-safe (constraint decoding)
- Cache-friendly (fixed small set)

**LAYER 2: Sandbox Utilities (CLI tools)**
- Pre-installed in sandbox/environment
- Accessed via shell tool (no new function definitions!)
- Examples: format converters, MCP CLI, speech recognition
- AI uses: `execute_shell("mcp-cli search 'pricing'")`

**LAYER 3: Code/APIs (Python scripts)**
- Write Python to call APIs, process data
- Accessed via write_file + execute_shell
- Good for: large computations, API chaining, data processing
- Example: Analyze year of stock data → compute in Python → return summary

```python
# Customer Agent only has ~10 atomic functions in function calling schema
tools = [
    "read_file",
    "write_file",
    "execute_shell",
    "search_knowledge",
    "get_customer_data",
    "book_appointment",
    "send_payment_link",
    "escalate_to_human"
]

# Everything else accessed via shell or code
# AI: execute_shell("format-converter pdf-to-text menu.pdf")
# AI: execute_shell("python analyze_data.py")
```

**BENEFITS:**
- No tool explosion (function calling stays small)
- KV cache friendly (atomic tools don't change)
- Unlimited extensibility (via sandbox/code)
- Models already trained on this pattern

**MANIS: Keep atomic functions under 30. Offload rest to sandbox/code.**


SOLUTION 2: Compaction vs Summarization (MANIS TECHNIQUE)
----------------------------------------------------------

**Two DIFFERENT operations:**

**COMPACTION (Reversible Reduction):**
- Full data → file system
- Compact version → context (just pointer)
- Can always retrieve full data if needed

Example:
```python
# Tool writes large content
full_output = {
    "path": "data/analysis.json",
    "content": "... 50KB of data ..."
}

# Compact version in context
compact_output = {
    "path": "data/analysis.json"
    # Content omitted, can be read via path
}
```

**SUMMARIZATION (Irreversible):**
- Use structured schemas (not free-form!)
- Offload pre-summary context to files first
- Keep last few tool calls in full detail (few-shot examples)

**MANIS THRESHOLDS:**
```
Hard limit: 1M tokens (model max)
Pre-rot threshold: 128K-200K (quality degrades)
    ↓
Trigger compaction (oldest 50% of tool calls)
    ↓
Check gain. If small:
    ↓
Trigger summarization (use schema, keep recent examples)
```

**KEY: Compaction first (reversible), summarization only when needed.**


SOLUTION 3: Multi-Model Routing (Cost Optimization)
----------------------------------------------------

Route to cheapest model that can handle task.

```python
# Simple FAQ → Gemini Flash (FREE!)
if is_simple_faq(message):
    response = gemini_flash.generate(...)

# Complex reasoning → GPT-4o-mini
elif is_complex(message):
    response = gpt4_mini.generate(...)

# Critical actions → GPT-4
elif needs_reliability(message):
    response = gpt4.generate(...)
```

**MANIS:** Different models excel at different tasks:
- Claude: Coding, tool use
- Gemini: Multimodal, speed
- GPT-4: Math, reasoning

Route by task, not just cost.

response = anthropic.messages.create(

SOLUTION 6: File System > Vector DB (For Bounded Contexts)
-----------------------------------------------------------

**MANIS DOESN'T USE VECTOR DBs** (for agent workspace)

Why:
- Each session is new sandbox
- Users want fast interaction
- No time to build index on-the-fly
- Glob/grep work well for code/files

**When to use vector DB:**
- Large knowledge bases (1000s of docs)
- Cross-session memory
- Semantic search needed

**When to use file system + glob/grep:**
- Session-based work (like code agents)
- Structured files (code, configs)
- Fast setup required

**FOR US:**
- Customer Agent knowledge blocks → vector DB (pgvector)
- Builder AI workspace → file system + glob/grep
- Best of both worlds


SOLUTION 7: Structured State > Full Message History
----------------------------------------------------

**Extract facts, not store raw messages:**

```python
class ConversationFacts(BaseModel):
    customer_name: str | None
    intent: str  # "booking" | "question" | "complaint"
    service_interested: str | None
    datetime_requested: str | None
    preferences: Dict[str, Any]
    questions_asked: List[str]

# After each turn, extract facts
facts = extractor.extract(
    conversation=messages,
    response_model=ConversationFacts
)

# Only send: facts + last 2-3 messages
context = {
    "facts": facts,
    "recent_messages": messages[-3:]
}
```

**Benefits:**
- Tiny context
- Cheap
- Can still answer "What did I ask yesterday?"


CUTTING-EDGE TECHNIQUES:
========================

1. AGENTIC RAG
--------------
Agent decides what to retrieve and when (not just dump everything).

```python
tools = [
    search_products,
    search_faq,
    search_past_conversations
]

# Agent iterates: search → refine query → search again
```

**Tools:** LangGraph + multiple retrievers, LlamaIndex Agents


2. REACT PATTERN
----------------
Think → Act → Observe → Think → Act (not just think once)

```python
# Turn 1: Think
"User wants to book. Need service, date, time."

# Turn 1: Act
ask_question("What service?")

# Turn 2: Observe
"Haircut"

# Turn 2: Think
"Got service. Still need date/time."

# Turn 2: Act
ask_question("What date/time?")

# ... continues until all info collected
```

**More reliable, self-correcting, transparent.**


3. CONSTITUTIONAL AI
--------------------
AI self-validates against principles (built into Claude).

```python
principles = [
    "Never use emojis",
    "Always be professional",
    "Escalate if uncertain"
]

# AI generates response
response = ai.generate(message)

# AI self-critiques
if violates_principles(response, principles):
    response = ai.regenerate(constraints=principles)
```

**Fewer validation loops, more reliable.**

KEY MANIS LESSONS:
==================

1. **Don't Over-Engineer**
   - Biggest improvements came from REMOVING complexity
   - Trust models more, build less scaffolding
   - Simplify architecture as models improve

2. **Use Schemas Everywhere**
   - Summarization → structured schema (not free-form)
   - Sub-agent communication → enforce output schemas
   - Block creation → structured formats

3. **Layer Your Action Space**
   - Atomic functions (10-20 max)
   - Sandbox utilities (via shell)
   - Code/APIs (via write + execute)
   - Keeps function calling lean and cache-friendly

4. **Test with Weak Models**
   - Toggle between weak/strong models
   - If weak→strong gives big gains, architecture is future-proof
   - Helps prepare for next model release

5. **Agent-as-Tool Pattern**
   - Complex tasks → spawn specialist sub-agent
   - Main agent defines output schema
   - Sub-agent must conform (constraint decoding)
   - Better than permanent multi-agent swarm

6. **Context Thresholds Matter**
   - Hard limit (model max): 1M tokens
   - Pre-rot threshold (quality drops): 128K-200K
   - Trigger compaction at pre-rot
   - Summarize only if compaction doesn't help

7. **File System vs Vector DB**
   - Session work (code, agent workspace) → file system
   - Large persistent knowledge → vector DB
   - Both have their place
