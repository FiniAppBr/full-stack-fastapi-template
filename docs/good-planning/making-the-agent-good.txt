Making the Customer Agent Actually Good
=========================================

THE CORE CHALLENGE:
-------------------

The builder interface (chat + blocks) is just UI/UX.
The real challenge: Making the customer-facing AI agent actually GOOD.

What we need:
- Natural conversation (like ChatGPT)
- Reliable actions (like traditional chatbots)
- Controllable behavior (respects configured blocks)
- No hallucinations (only uses configured knowledge)
- Knows when to escalate (doesn't pretend to know everything)


THE PROBLEM WITH NAIVE APPROACHES:
-----------------------------------

❌ Traditional Chatbots:
- Follow rigid scripts
- Predictable but not natural
- Can't handle variations in language

❌ Pure LLM (like ChatGPT API):
- Natural but unreliable
- Hallucinates information
- No control over behavior
- Makes stuff up

✅ What We Need:
- Natural + Reliable + Controllable
- Uses only configured knowledge
- Can take real actions (booking, payments)
- Respects personality settings
- Escalates when uncertain


HOW TO MAKE THE AGENT GOOD:
============================

1. KNOWLEDGE RETRIEVAL (Not Just Prompting)
--------------------------------------------

BAD APPROACH:
```python
# Dump everything into prompt
prompt = f"""
You are a customer service agent for {business_name}.

Here's all our info:
{dump_all_blocks_into_prompt}  # 50,000 tokens!

Customer: {customer_message}
"""
```

Problems:
- Hits context window limits
- Expensive (tokens cost money)
- AI might misremember or confuse info
- Can't scale to large knowledge bases

GOOD APPROACH: Retrieval Augmented Generation (RAG)
```python
# 1. Embed customer message
query_embedding = embed(customer_message)

# 2. Semantic search against knowledge blocks
relevant_blocks = vector_search(
    query_embedding=query_embedding,
    blocks=agent.knowledge_blocks,
    top_k=3  # Only get top 3 most relevant
)

# 3. Inject only relevant context
prompt = f"""
You are a customer service agent.

RELEVANT INFORMATION:
{relevant_blocks}  # Only ~1000 tokens

PERSONALITY: {personality_block}
RULES: {rule_blocks}

Customer: {customer_message}
"""
```

Benefits:
- Scales to unlimited knowledge
- Only uses relevant info (less confusion)
- More accurate, less hallucination
- Cheaper (fewer tokens)

IMPLEMENTATION:
- Store block content in vector database
- Embed customer message
- Retrieve top 3-5 most relevant blocks
- Inject only those into prompt


2. STRUCTURED ACTIONS (Not Just Text)
--------------------------------------

BAD APPROACH:
Let AI only generate text responses, hope it says the right thing

GOOD APPROACH:
AI can invoke ACTIONS via function/tool calling

```python
# Define tools the AI can use
tools = [
    {
        "name": "check_availability",
        "description": "Check appointment availability",
        "parameters": {
            "date": "string",
            "service": "string"
        }
    },
    {
        "name": "create_appointment",
        "description": "Book an appointment",
        "parameters": {
            "datetime": "string",
            "service": "string",
            "customer_name": "string"
        }
    },
    {
        "name": "get_pricing",
        "description": "Get accurate price for a service",
        "parameters": {
            "service_name": "string"
        }
    },
    {
        "name": "escalate_to_human",
        "description": "Hand off conversation to human agent",
        "parameters": {
            "reason": "string",
            "urgency": "low|medium|high"
        }
    }
]
```

EXAMPLE CONVERSATION:
> Customer: "Can I book a haircut for tomorrow at 2pm?"

AI reasoning:
1. Need to check availability first
2. Call `check_availability(date="2024-10-25", service="haircut")`
3. Get result: `{"available": true, "stylist": "Maria"}`
4. Call `create_appointment(datetime="2024-10-25T14:00", ...)`
5. Get result: `{"success": true, "confirmation": "APPT-123"}`
6. Respond: "Perfect! You're booked with Maria tomorrow at 2pm. Confirmation: APPT-123"

WHY THIS MATTERS:
- Actions are RELIABLE (not just suggestions in text)
- Integrates with real systems (calendars, payments, CRMs)
- Separates "what to do" from "how to say it"
- Can verify actions succeeded before confirming to customer


3. CONVERSATION STATE MANAGEMENT
---------------------------------

BAD APPROACH:
Send entire conversation history every time (expensive, slow, hits limits)

GOOD APPROACH:
Track conversation state explicitly

```python
class ConversationState:
    intent: str  # "asking_price" | "booking_appointment" | "complaint"
    collected_data: dict  # Information gathered so far
    next_step: str  # What AI should do next
    missing_info: list  # What we still need to ask
    context: list  # Relevant blocks for this conversation
```

EXAMPLE STATE EVOLUTION:

Message 1: "I want to book a haircut"
State:
```json
{
    "intent": "booking_appointment",
    "collected_data": {"service": "haircut"},
    "next_step": "ask_datetime",
    "missing_info": ["datetime", "customer_name"],
    "context": ["appointment_block", "pricing_block"]
}
```

Message 2: "Tomorrow at 2pm"
State:
```json
{
    "intent": "booking_appointment",
    "collected_data": {
        "service": "haircut",
        "datetime": "2024-10-25T14:00"
    },
    "next_step": "ask_name",
    "missing_info": ["customer_name"],
    "context": ["appointment_block"]
}
```

Message 3: "João Silva"
State:
```json
{
    "intent": "booking_appointment",
    "collected_data": {
        "service": "haircut",
        "datetime": "2024-10-25T14:00",
        "customer_name": "João Silva"
    },
    "next_step": "confirm_booking",
    "missing_info": [],
    "context": ["appointment_block"]
}
```

BENEFITS:
- Don't need to re-analyze entire conversation
- Know exactly what information is still missing
- Can resume conversations cleanly
- Cheaper (send less context to LLM)
- Explicit control over conversation flow


4. GUARDRAILS & VALIDATION
---------------------------

The blocks define constraints. AI must respect them.

PERSONALITY VALIDATION:
```python
# Personality block says: "Never use emojis"
def validate_response(response, personality_block):
    if personality_block.no_emojis:
        if has_emojis(response):
            # Regenerate without emojis
            return regenerate_response(
                original=response,
                constraint="no_emojis"
            )
    return response
```

AUTOMATIC ESCALATION:
```python
# Handoff block says: "Escalate if customer seems angry"
def check_escalation(message, handoff_block):
    sentiment = analyze_sentiment(message)

    if sentiment == "angry" and handoff_block.escalate_on_anger:
        return trigger_handoff(
            reason="customer_angry",
            urgency="high"
        )

    return continue_conversation()
```

FACT CHECKING:
```python
# Don't let AI make up prices
def validate_pricing_response(response, pricing_blocks):
    mentioned_prices = extract_prices(response)

    for price in mentioned_prices:
        if not price_exists_in_blocks(price, pricing_blocks):
            # AI made up a price!
            return regenerate_with_constraint(
                "Only mention prices from the pricing block"
            )

    return response
```

KEY GUARDRAILS:
- Tone validation (matches personality block)
- Fact checking (only say things in knowledge base)
- Action permissions (can AI book? take payments?)
- Safety filters (don't respond to abuse, don't leak sensitive data)
- Language validation (stay in configured languages)


5. HANDLING UNCERTAINTY
------------------------

CRITICAL: AI must know when it doesn't know.

CONFIDENCE-BASED ESCALATION:
```python
# AI generates response with confidence score
response = agent.respond(message)

if response.confidence < 0.7:
    # Don't guess - be honest
    return {
        "message": "I'm not sure about that. Let me connect you with someone who can help.",
        "action": "escalate_to_human",
        "reason": "uncertain"
    }
```

KNOWLEDGE GAP DETECTION:
```python
# Check if query matches any knowledge block
relevant_blocks = search_knowledge(message, threshold=0.6)

if not relevant_blocks:
    # No relevant information found
    return {
        "message": "I don't have information about that yet. Would you like to speak with our team?",
        "action": "offer_escalation"
    }
```

THIS PREVENTS:
- Hallucinations ("Our price is R$500" when it's actually R$300)
- Making stuff up ("Yes we deliver!" when they don't)
- Giving wrong information
- Frustrating customers with confident wrong answers

=============================================

Customer WhatsApp message arrives
    ↓
Temporal Workflow: customer-agent-{business_id}-{customer_id}-{session_id}
    ↓
[STAGE 1: INTENT CLASSIFICATION]
    Component: classify_customer_intent (Temporal Activity)

    Input: Customer message + customer context
    Output: Structured intent with:
      - Intent type: "booking", "question", "complaint", "payment"

      - Extracted parameters: date, service name, etc.
    Time: ~500ms
    ↓
[STAGE 2: KNOWLEDGE RETRIEVAL (RAG)]
    Component: retrieve_knowledge (Temporal Activity)
    Tool: pgvector semantic search
    Process:
      - Embed customer query
      - Search knowledge_chunks table
      - Return top 3 most relevant chunks
    Strategies:
      - v0.1: PostgreSQL full-text (<200ms, 70% accuracy)
      - v0.3: pgvector semantic (<100ms, 85% accuracy)
      - v1.0: Hybrid 70% semantic + 30% keyword (<20ms, 90% accuracy)
    Time: ~100-200ms
    ↓
[STAGE 3: LONG-TERM MEMORY RETRIEVAL]
    Component: Mem0 Integration (Optional v0.3+)
    Query: "What does this customer prefer?"
    Returns: Customer facts, preferences, history
      - Allergies
      - Appointment preferences
      - Past conversations
      - Service history
    Time: ~100ms
    ↓
[STAGE 4: RESPONSE GENERATION]
    Component: generate_customer_response (Temporal Activity)
    Model: Gemini Flash 2.5 (more capable than 2.0)
    Input:
      - Intent (what customer wants)
      - Retrieved knowledge blocks (top 3)
      - Personality block (tone, emoji usage, language)
      - Customer context (past preferences)
      - Memory from Mem0
    Constraints:
      - Personality validation (no emojis if configured)
      - Fact checking (only prices/info in blocks)
      - Tone matching (formal vs friendly)
      - Language (Portuguese only)
    Output: Natural conversational response
    Time: ~1-2 seconds
    ↓
[STAGE 5: GUARDRAILS VALIDATION]
    Component: Guardrails AI (v0.2+)
    Checks:
      - Personality validation: Matches configured tone?
      - Fact check: Is mentioned price in knowledge base?
      - Safety: No sensitive data leaked?
      - Escalation triggers: Customer angry? Uncertain?
    If fails: Regenerate with constraints
    Time: ~200ms
    ↓
[STAGE 6: ACTION EXECUTION (If Needed)]
    Component: execute_action (Temporal Activity)
    Condition: If intent.action_needed == True
    Available Actions (from Action Blocks):
      - Book appointment (Google Calendar)
      - Send payment link (Stripe)
      - Send email notification (SendGrid)
      - Check inventory
      - Create form submission
    Process:
      1. Validate parameters
      2. Call external API
      3. Return result (success/failure)
      4. Update customer context
    Time: ~500ms - 2 seconds
    ↓
[STAGE 7: MEMORY PERSISTENCE & ANALYTICS]
    Component: Background activities
    Actions:
      - Save to Mem0: preferences, context, actions
      - Update customer profile
      - Log analytics: satisfaction, escalation, actions
      - Record failure modes
    Time: Async (doesn't block response)
    ↓
Response sent to WhatsApp

TOTAL TIME: ~2-5 seconds per message
COST: ~$0.02 per 20-turn conversation (90% free via Gemini Flash)

-----------------------------------------

What it does:

- Define conversation flows as graphs
- Track state across conversation turns
- Handle complex branching logic

How it helps us:
- Manages conversation state automatically

```python

# Define conversation flow
```

Why use it:

Use case for us:

- Can generate flows automatically from blocks

4. VECTOR DATABASES
--------------------

Options:
- **Pinecone** (managed, easy to use, $$$)
- **Weaviate** (open source, powerful, self-host or cloud)
- **Qdrant** (open source, fast, Python-friendly)
- **pgvector** (PostgreSQL extension, use existing DB)

What they do:
- Store embeddings of text
- Fast semantic search
- Find similar content

How it helps us:
- Store all knowledge blocks as vectors
- Retrieve relevant blocks for customer queries
- Scale to thousands of documents
- Sub-second search

Example with pgvector (use our existing PostgreSQL):
```python
from pgvector.sqlalchemy import Vector
from sqlalchemy import create_engine

# Store knowledge blocks with embeddings
class KnowledgeBlock(Base):
    id = Column(Integer, primary_key=True)
    content = Column(Text)
    embedding = Column(Vector(1536))  # OpenAI embedding dimension

# Search
def search_knowledge(query: str, top_k: int = 3):
    query_embedding = get_embedding(query)

    results = session.query(KnowledgeBlock).order_by(
        KnowledgeBlock.embedding.cosine_distance(query_embedding)
    ).limit(top_k).all()

    return results
```

Why use pgvector specifically:
- Already using PostgreSQL
- No new infrastructure
- Good enough performance for most cases
- Free

Use case for us:
- Store all document blocks, text blocks, FAQ blocks
- Semantic search when customer asks questions
- Can upgrade to Pinecone/Weaviate later if needed

CONCRETE ARCHITECTURE WITH TEMPORAL:
=====================================

```python
from temporalio import workflow, activity
from instructor import from_openai
from openai import OpenAI
from pydantic import BaseModel

# Pydantic models for structured outputs
class CustomerIntent(BaseModel):
    intent_type: str  # "booking", "question", "complaint"
    query: str
    action_needed: bool
    confidence: float
    extracted_params: dict

class KnowledgeResult(BaseModel):
    chunks: list[str]
    sources: list[str]
    relevance_scores: list[float]

# Temporal Activities (each stage is an activity)
@activity.defn
async def classify_customer_intent(message: str, customer_id: str) -> CustomerIntent:
    """Stage 1: Classify what customer wants using Gemini Flash 2.0"""
    client = from_openai(OpenAI())

    intent = client.chat.completions.create(
        model="gemini-flash-2.0",  # Fast, cheap, FREE
        response_model=CustomerIntent,
        messages=[
            {"role": "system", "content": "Classify customer intent accurately"},
            {"role": "user", "content": message}
        ]
    )

    return intent

@activity.defn
async def retrieve_knowledge(query: str, agent_id: str, top_k: int = 3) -> KnowledgeResult:
    """Stage 2: Retrieve relevant knowledge chunks via semantic search"""
    from app.database import get_session
    from app.models import KnowledgeChunk

    session = get_session()

    # v0.1: PostgreSQL full-text search
    results = session.execute(f"""
        SELECT content, metadata, ts_rank(to_tsvector(content), plainto_tsquery('{query}')) as score
        FROM knowledge_chunks
        WHERE agent_id = '{agent_id}'
        ORDER BY score DESC
        LIMIT {top_k}
    """).fetchall()

    return KnowledgeResult(
        chunks=[r[0] for r in results],
        sources=[r[1].get('source', 'unknown') for r in results],
        relevance_scores=[r[2] for r in results]
    )

@activity.defn
async def generate_customer_response(
    intent: CustomerIntent,
    knowledge: KnowledgeResult,
    personality: dict,
    memories: list[str]
) -> str:
    """Stage 4: Generate natural response with all context"""
    client = OpenAI()

    response = client.chat.completions.create(
        model="gemini-flash-2.5",  # More capable for generation
        messages=[
            {
                "role": "system",
                "content": f"""You are a customer service agent.

                PERSONALITY: {personality.get('tone')} tone, {personality.get('emoji_usage')}

                RELEVANT KNOWLEDGE:
                {chr(10).join(knowledge.chunks)}

                CUSTOMER CONTEXT:
                {chr(10).join(memories)}

                Rules:
                - Only use information from RELEVANT KNOWLEDGE
                - Match the personality tone
                - Be helpful and concise
                - Escalate if uncertain (confidence < 0.7)
                """
            },
            {"role": "user", "content": intent.query}
        ]
    )

    return response.choices[0].message.content

@activity.defn
async def execute_action(action_type: str, params: dict) -> dict:
    """Stage 6: Execute action (booking, payment, etc.)"""
    from app.tools import ToolRegistry

    tool = ToolRegistry.get_tool(action_type)
    result = await tool.execute(params)

    return result

# Temporal Workflow (orchestrates all activities)
@workflow.defn
class CustomerAgentWorkflow:
    """One workflow per customer conversation"""

    @workflow.run
    async def run(self, message: str, customer_id: str, agent_id: str):
        # Load blocks once
        blocks = await workflow.execute_activity(
            load_agent_blocks,
            agent_id,
            start_to_close_timeout=timedelta(seconds=5)
        )

        # Stage 1: Classify intent
        intent = await workflow.execute_activity(
            classify_customer_intent,
            args=[message, customer_id],
            start_to_close_timeout=timedelta(seconds=5)
        )

        # Stage 2: Retrieve knowledge
        knowledge = await workflow.execute_activity(
            retrieve_knowledge,
            args=[intent.query, agent_id],
            start_to_close_timeout=timedelta(seconds=5)
        )

        # Stage 3: Get customer memory (optional v0.3+)
        memories = await workflow.execute_activity(
            get_customer_memories,
            args=[customer_id],
            start_to_close_timeout=timedelta(seconds=2)
        )

        # Stage 4: Generate response
        response = await workflow.execute_activity(
            generate_customer_response,
            args=[intent, knowledge, blocks.personality, memories],
            start_to_close_timeout=timedelta(seconds=10)
        )

        # Stage 5: Validate with guardrails (v0.2+)
        validated_response = await workflow.execute_activity(
            validate_response,
            args=[response, blocks.personality],
            start_to_close_timeout=timedelta(seconds=2)
        )

        # Stage 6: Execute action if needed
        action_result = None
        if intent.action_needed:
            action_result = await workflow.execute_activity(
                execute_action,
                args=[intent.intent_type, intent.extracted_params],
                start_to_close_timeout=timedelta(seconds=30)
            )

        # Stage 7: Save memory (async, doesn't block)
        workflow.execute_activity(
            save_customer_memory,
            args=[customer_id, message, validated_response],
            start_to_close_timeout=timedelta(seconds=5)
        )

        return {
            "response": validated_response,
            "action_result": action_result,
            "intent": intent,
            "knowledge_used": knowledge.sources
        }
```


WHAT MAKES THE AGENT "GOOD" - CHECKLIST:
=========================================

✅ **Accurate** - Doesn't hallucinate, uses only configured knowledge
✅ **Reliable** - Actions work (bookings succeed, payments process)
✅ **Natural** - Sounds human, not robotic
✅ **Appropriate** - Matches configured personality (formal vs casual)
✅ **Helpful** - Actually solves customer problems
✅ **Honest** - Says "I don't know" instead of guessing
✅ **Respectful** - Escalates when customer is frustrated
✅ **Fast** - Responds in <2 seconds
✅ **Consistent** - Same question → same answer (mostly)
✅ **Learns** - Gets better over time from failures


THE HARDEST PARTS (And How Tech Helps):
========================================

1. **Context handling** (when to remember vs forget)
   → Solution: Mem0 handles this automatically

2. **Ambiguity** ("I want to book" - which service? when?)
   → Solution: Instructor extracts structured intent, LangGraph manages state

3. **Multi-turn** (collecting info over several messages)
   → Solution: LangGraph conversation flows

4. **Error recovery** (calendar is down, payment fails)
   → Solution: LangGraph can define fallback paths

5. **Edge cases** (rude customers, nonsense messages)
   → Solution: Guardrails + sentiment analysis

6. **Language nuance** (sarcasm, idioms, typos)
   → Solution: GPT-4 is good at this, improve prompts over time

7. **Knowing when to give up** (don't loop forever)
   → Solution: Max turns in LangGraph, escalation logic
