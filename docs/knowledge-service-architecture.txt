Knowledge Service Architecture - Complete System Design
================================================================

THE CHALLENGE:
--------------

We need a robust system where:
- Users upload ANY file type (PDF, DOCX, XLSX, images, TXT)
- System extracts knowledge automatically
- Agent can retrieve relevant knowledge INSTANTLY
- Scales to 100+ knowledge blocks per agent
- Works reliably regardless of content type

You're right - this is NOT simple. Let's break it down.


THE PIPELINE (7 Stages):
========================

Customer uploads file
    ↓
[1. FILE INGESTION] - Accept upload, validate, store original
    ↓
[2. FILE TYPE DETECTION] - What kind of file is this?
    ↓
[3. CONTENT EXTRACTION] - Pull text/data from file
    ↓
[4. CONTENT PROCESSING] - Clean, structure, chunk
    ↓
[5. VECTORIZATION] - Create embeddings for semantic search
    ↓
[6. STORAGE] - Save to database + vector store
    ↓
[7. RETRIEVAL] - Fast semantic search when agent needs knowledge


STAGE 1: FILE INGESTION
========================

What happens when user uploads a file.

TECHNOLOGIES:
- FastAPI file upload (UploadFile)
- File validation
- S3 or local filesystem storage

PROCESS:
```python
@router.post("/api/v1/agents/{agent_id}/knowledge/upload")

    agent_id: int,

    # 3. Create knowledge block (status=processing)
    block = crud.create_block(

        config={
            "source_type": "file",

        }

    # 4. Queue for async processing
    celery_task.delay(block.id)

```

VALIDATION RULES:
- Max file size: 50MB (configurable)
- Allowed types: PDF, DOCX, XLSX, TXT, PNG, JPG (more later)
- Malware scan: Use clamd or VirusTotal API
- Auth check: User owns this agent

STORAGE:
- v0.1: Local filesystem `/uploads/agent_{id}/`
- v1.0: S3-compatible storage (MinIO, AWS S3, DigitalOcean Spaces)

WHY ASYNC:
- File processing can take 5-30 seconds
- Don't block API response
- User sees "Processing..." then gets notification when ready


STAGE 2: FILE TYPE DETECTION
=============================

Determine what kind of file we're dealing with.

TECHNOLOGIES:
- python-magic (libmagic wrapper - reads file signatures)
- mimetypes (standard library)
- File extension as fallback

PROCESS:
```python
import magic

def detect_file_type(file_path: str) -> FileType:
    # 1. Use magic to read file signature (most reliable)
    mime = magic.from_file(file_path, mime=True)

    # 2. Map MIME type to our internal type
    type_map = {
        "application/pdf": FileType.PDF,
        "application/vnd.openxmlformats-officedocument.wordprocessingml.document": FileType.DOCX,
        "application/vnd.ms-word": FileType.DOC,
        "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet": FileType.XLSX,
        "application/vnd.ms-excel": FileType.XLS,
        "text/plain": FileType.TXT,
        "image/png": FileType.IMAGE,
        "image/jpeg": FileType.IMAGE,
        "text/csv": FileType.CSV,
    }

    return type_map.get(mime, FileType.UNKNOWN)
```

FILE TYPES WE SUPPORT:

TEXT-BASED:

STRUCTURED DATA:

IMAGES:

3A. PDF EXTRACTION
-------------------

CHALLENGE: PDFs can be:
- Text-based (selectable text) - easy
- Image-based (scanned documents) - needs OCR
- Mixed (text + images + tables) - complex

TECHNOLOGIES:
- pypdf or PyMuPDF (fitz) - extract text from text-based PDFs
- pdfplumber - better for tables
- pytesseract + pdf2image - OCR for scanned PDFs

PROCESS:
```python
import fitz  # PyMuPDF
import pdfplumber
from pdf2image import convert_from_path
import pytesseract

def extract_pdf_content(file_path: str) -> dict:
    """Extract text, tables, and images from PDF"""

    # 1. Try text extraction first (fast)
    text = extract_text_pypdf(file_path)

    # 2. If very little text found, probably scanned - use OCR
    if len(text.strip()) < 100:
        text = extract_text_ocr(file_path)

    # 3. Extract tables separately (structured data)
    tables = extract_tables_pdf(file_path)

    # 4. Extract images (for future image analysis)
    images = extract_images_pdf(file_path)

    return {
        "text": text,
        "tables": tables,
        "images": images,
        "extraction_method": "text" if text else "ocr"
    }


def extract_text_pypdf(file_path: str) -> str:
    """Fast text extraction for text-based PDFs"""
    doc = fitz.open(file_path)
    text = ""
    for page in doc:
        text += page.get_text()
    return text


def extract_text_ocr(file_path: str) -> str:
    """OCR for scanned PDFs"""
    images = convert_from_path(file_path, dpi=300)
    text = ""
    for image in images:
        text += pytesseract.image_to_string(image, lang='eng+por')
    return text


def extract_tables_pdf(file_path: str) -> list[dict]:
    """Extract tables as structured data"""
    tables = []
    with pdfplumber.open(file_path) as pdf:
        for page in pdf.pages:
            page_tables = page.extract_tables()
            for table in page_tables:
                # Convert to dict with headers
                if table and len(table) > 1:
                    headers = table[0]
                    for row in table[1:]:
                        tables.append(dict(zip(headers, row)))
    return tables
```

def extract_docx_content(file_path: str) -> dict:
    """Extract text and tables from Word document"""
    doc = Document(file_path)

    text = "\n".join([p.text for p in doc.paragraphs])

3C. EXCEL/SPREADSHEET EXTRACTION
---------------------------------

TECHNOLOGIES:
- pandas - read Excel/CSV
- openpyxl - lower-level Excel manipulation

PROCESS:
```python
import pandas as pd

def extract_excel_content(file_path: str) -> dict:
    """Extract all sheets from Excel as structured data"""

    # 1. Read all sheets
    excel_file = pd.ExcelFile(file_path)
    sheets = {}

    for sheet_name in excel_file.sheet_names:
        df = pd.read_excel(excel_file, sheet_name=sheet_name)

        # 2. Convert to JSON-friendly format
        sheets[sheet_name] = df.to_dict('records')

    # 3. Also generate plain text version for semantic search
    text = generate_text_from_sheets(sheets)

    return {
        "sheets": sheets,
        "text": text  # For vector search
    }


def generate_text_from_sheets(sheets: dict) -> str:
    """Convert spreadsheet to searchable text"""
    text = ""
    for sheet_name, rows in sheets.items():
        text += f"\n\n{sheet_name}:\n"
        for row in rows:
            text += " | ".join([f"{k}: {v}" for k, v in row.items()]) + "\n"
    return text
```

STAGE 4: CONTENT PROCESSING
============================

Clean, structure, and chunk the extracted content.

WHY CHUNK?
- LLMs have context limits (4k, 8k, 128k tokens)
- Vector search works better on smaller chunks
- More precise retrieval ("which chunk answers this question?")

TECHNOLOGIES:
- LangChain RecursiveCharacterTextSplitter
- tiktoken (count tokens accurately)
- Custom chunking logic for structured data

PROCESS:
```python
from langchain.text_splitter import RecursiveCharacterTextSplitter
import tiktoken

def process_content(extracted_content: dict, file_type: FileType) -> dict:
    """Clean, structure, and chunk content"""

    # 1. Get raw text
    text = extracted_content.get("text", "")

    # 2. Clean text
    text = clean_text(text)

    # 3. Chunk text for vector search
    chunks = chunk_text(text, chunk_size=500, overlap=50)

    # 4. Handle structured data separately
    structured_data = None
    if file_type in [FileType.XLSX, FileType.CSV]:
        structured_data = extracted_content.get("sheets")
    elif file_type == FileType.PDF and extracted_content.get("tables"):
        structured_data = extracted_content.get("tables")

    return {
        "text": text,  # Full text
        "chunks": chunks,  # For vector search
        "structured_data": structured_data,  # For exact queries
        "metadata": {
            "num_chunks": len(chunks),
            "num_tokens": count_tokens(text),
            "file_type": file_type
        }
    }


def clean_text(text: str) -> str:
    """Remove noise from extracted text"""
    # Remove excessive whitespace
    text = re.sub(r'\s+', ' ', text)

    # Remove page numbers (e.g., "Page 1 of 10")
    text = re.sub(r'Page \d+ of \d+', '', text)

    # Remove headers/footers (common patterns)
    text = re.sub(r'^.*?www\..*?com.*?$', '', text, flags=re.MULTILINE)

    # Normalize currency (R$ 100, R$100, 100 reais → R$100)
    text = normalize_currency(text)

    return text.strip()


def chunk_text(text: str, chunk_size: int = 500, overlap: int = 50) -> list[str]:
    """Split text into overlapping chunks"""
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size,
        chunk_overlap=overlap,
        separators=["\n\n", "\n", ". ", " ", ""]  # Try to split on paragraph/sentence boundaries
    )

    chunks = splitter.split_text(text)
    return chunks


def count_tokens(text: str, model: str = "gpt-4") -> int:
    """Count tokens accurately"""
    encoding = tiktoken.encoding_for_model(model)
    return len(encoding.encode(text))
```

CHUNKING STRATEGY:

For general text:
- Chunk size: 500-1000 characters (~125-250 tokens)
- Overlap: 50-100 characters (preserve context across chunks)
- Split on: paragraphs > sentences > words

For structured data (pricing tables):
- Each row = one chunk (so searches return exact price)
- Example: "Bath service for medium dogs: R$80"

For FAQs:
- Each Q&A pair = one chunk
- Example: "Q: Do you deliver? A: We don't offer delivery, but we do pickup."

Input: Restaurant menu (3 pages, 2000 words)

Output:

STAGE 5: VECTORIZATION
=======================

Convert text chunks to embeddings for semantic search.

WHY EMBEDDINGS?
- Customer asks: "How much for a haircut?"
- Text chunk says: "Men's cut - R$50"
- Keywords don't match ("haircut" ≠ "cut")
- But embeddings are similar (cosine similarity ~0.85)
- Semantic search finds the right chunk

TECHNOLOGIES:

Option 1: OpenAI Embeddings
- Model: text-embedding-3-small (1536 dimensions)
- Cost: $0.02 per 1M tokens (cheap)
- Quality: Excellent
- Speed: 100ms per request

Option 2: HuggingFace (Local, Free)
- Model: all-MiniLM-L6-v2 (384 dimensions)
- Cost: FREE (run locally)
- Quality: Good (slightly worse than OpenAI)
- Speed: 20ms per chunk (faster, local)

Option 3: Cohere Embeddings
- Model: embed-multilingual-v3 (1024 dimensions)
- Cost: $0.10 per 1M tokens
- Quality: Best for non-English (Portuguese!)
- Speed: Similar to OpenAI

RECOMMENDATION FOR v0.1:
Use HuggingFace (free, good enough, local)
Upgrade to OpenAI in v1.0 if quality issues

PROCESS:
```python
from sentence_transformers import SentenceTransformer

# Load model once at startup
embedding_model = SentenceTransformer('all-MiniLM-L6-v2')

def vectorize_chunks(chunks: list[str]) -> list[list[float]]:
    """Convert text chunks to embeddings"""

    # Batch embedding (faster than one-by-one)
    embeddings = embedding_model.encode(
        chunks,
        batch_size=32,
        show_progress_bar=True
    )

    return embeddings.tolist()  # Convert numpy to list for JSON storage
```

EXAMPLE:

Input:
```python
chunks = [
    "Bath service for small dogs costs R$60",
    "Full grooming for medium dogs is R$120",
    "We offer nail trimming for R$30"
]
```

Output:
```python
embeddings = [
    [0.234, -0.112, 0.445, ..., 0.089],  # 384 numbers for chunk 1
    [0.156, -0.089, 0.512, ..., 0.234],  # 384 numbers for chunk 2
    [0.298, -0.145, 0.378, ..., 0.156]   # 384 numbers for chunk 3
]
```

OPTIMIZATION:
- Cache embeddings (don't re-compute unless text changes)
- Batch processing (embed 100 chunks at once, not 1 at a time)
- Use GPU if available (10x faster)

STAGE 7: RETRIEVAL (The Most Important Part)
=============================================

RETRIEVAL METHODS:

7A. Semantic Search (Primary Method)
-------------------------------------

Uses vector embeddings to find relevant chunks.

PROCESS:
```python
def retrieve_knowledge(agent_id: int, query: str, top_k: int = 3) -> list[dict]:
    """Find most relevant knowledge chunks for a query"""

    # 1. Embed the query
    query_embedding = embedding_model.encode([query])[0]

    # 2. Vector search in pgvector
    results = db.execute(
        """
        SELECT
            kc.chunk_text,
            kc.block_id,
            b.config->>'file_name' as file_name,
            1 - (kc.embedding <=> :query_embedding) as similarity
        FROM knowledge_chunk kc
        JOIN block b ON kc.block_id = b.id
        WHERE b.agent_id = :agent_id
        ORDER BY kc.embedding <=> :query_embedding
        LIMIT :top_k
        """,
        {
            "agent_id": agent_id,
            "query_embedding": query_embedding,
            "top_k": top_k
        }
    ).fetchall()

    return [
        {
            "text": r.chunk_text,
            "source": r.file_name,
            "similarity": r.similarity
        }
        for r in results
    ]
```

7B. Hybrid Search (Semantic + Keyword)
---------------------------------------

Combines vector search with traditional keyword search.

WHY?
- Semantic search sometimes misses exact matches
- Example: User says "R$80" in knowledge, customer asks "how much"
- Keyword search catches exact prices, names, SKUs

TECHNOLOGIES:
- pgvector for semantic
- PostgreSQL full-text search (tsvector) for keywords
- Combine scores with weighted average

PROCESS:
```python
def hybrid_search(agent_id: int, query: str, top_k: int = 3) -> list[dict]:
    """Combine semantic and keyword search"""

    # 1. Semantic search (vector)
    query_embedding = embedding_model.encode([query])[0]

    # 2. Keyword search (full-text)
    # Both searches in one SQL query
    results = db.execute(
        """
        WITH semantic_results AS (
            SELECT
                kc.id,
                kc.chunk_text,
                kc.block_id,
                (1 - (kc.embedding <=> :embedding)) as semantic_score
            FROM knowledge_chunk kc
            JOIN block b ON kc.block_id = b.id
            WHERE b.agent_id = :agent_id
        ),
        keyword_results AS (
            SELECT
                kc.id,
                ts_rank(to_tsvector('portuguese', kc.chunk_text),
                        plainto_tsquery('portuguese', :query)) as keyword_score
            FROM knowledge_chunk kc
            JOIN block b ON kc.block_id = b.id
            WHERE b.agent_id = :agent_id
        )
        SELECT
            sr.chunk_text,
            sr.block_id,
            (0.7 * sr.semantic_score + 0.3 * kr.keyword_score) as combined_score
        FROM semantic_results sr
        JOIN keyword_results kr ON sr.id = kr.id
        ORDER BY combined_score DESC
        LIMIT :top_k
        """,
        {
            "agent_id": agent_id,
            "query": query,
            "embedding": query_embedding,
            "top_k": top_k
        }
    ).fetchall()

    return results
```

WHEN TO USE:
- v0.1: Just semantic search (simpler)
- v1.0: Hybrid search (better accuracy)

7D. Caching (Performance Optimization)
---------------------------------------

Cache frequently accessed knowledge.

WHY?
- Same questions asked repeatedly ("hours?", "price?", "location?")
- Vector search is fast (~50ms) but can be faster
- Redis cache: <5ms

PROCESS:
```python
import redis
import hashlib

redis_client = redis.Redis()

def retrieve_knowledge_cached(agent_id: int, query: str, top_k: int = 3):
    """Retrieve with caching"""

    # 1. Generate cache key
    cache_key = f"knowledge:{agent_id}:{hashlib.md5(query.encode()).hexdigest()}"

    # 2. Check cache
    cached = redis_client.get(cache_key)
    if cached:
        return json.loads(cached)

    # 3. Query database (cache miss)
    results = retrieve_knowledge(agent_id, query, top_k)

    # 4. Store in cache (expire after 1 hour)
    redis_client.setex(cache_key, 3600, json.dumps(results))

    return results
```

CACHE INVALIDATION:
- When user updates/deletes a knowledge block
- Clear all cache for that agent_id
```python
redis_client.delete(f"knowledge:{agent_id}:*")
```

7E. Re-ranking (Advanced - v1.0)
--------------------------------

After retrieving top K chunks, re-rank them with a more powerful model.

WHY?
- Initial retrieval uses fast, simple embeddings
- Re-ranking uses smarter, slower model
- Gets top 10 chunks fast, then carefully picks best 3

TECHNOLOGIES:
- Cohere Rerank API
- CrossEncoder models (e.g., ms-marco-MiniLM)

PROCESS:
```python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-12-v2')

def retrieve_with_rerank(agent_id: int, query: str, top_k: int = 3):
    """Retrieve + rerank for better accuracy"""

    # 1. Get top 10 candidates (fast semantic search)
    candidates = retrieve_knowledge(agent_id, query, top_k=10)

    # 2. Score each candidate against query (slower but more accurate)
    pairs = [(query, c['text']) for c in candidates]
    scores = reranker.predict(pairs)

    # 3. Sort by new scores
    for i, score in enumerate(scores):
        candidates[i]['rerank_score'] = score

    candidates.sort(key=lambda x: x['rerank_score'], reverse=True)

    # 4. Return top K after reranking
    return candidates[:top_k]
```

WHEN TO USE:
- v0.1: Skip (adds complexity)
- v1.0: Add if retrieval accuracy is <85%

HANDLING MULTIPLE KNOWLEDGE BLOCKS
===================================

Challenge: Agent has 50 knowledge blocks. How do we search across all efficiently?

APPROACH 1: Search All (Current Design)
----------------------------------------

Search across ALL chunks from ALL blocks.

Pros:
- Simple
- Comprehensive
- Finds best match regardless of source

Cons:
- Slower with many blocks
- Can return irrelevant results

Works well for:
- <100 knowledge blocks
- <10,000 total chunks

---

APPROACH 2: Block-Level Filtering (v1.0 Optimization)
------------------------------------------------------

First filter which blocks are relevant, then search within those.

Example:
Customer asks: "What's your return policy?"

Step 1: Which blocks might contain return policy?
- "Store Policies.pdf" (high relevance)
- "FAQ.docx" (medium relevance)
- "Menu.pdf" (low relevance - skip)

Step 2: Search only within relevant blocks.

Implementation:
```python
def retrieve_with_block_filtering(agent_id: int, query: str):
    # 1. Get all blocks for this agent
    blocks = get_agent_blocks(agent_id, block_type="knowledge")

    # 2. Score each block's relevance to query
    block_scores = []
    for block in blocks:
        # Use block metadata (filename, first chunk) to estimate relevance
        score = score_block_relevance(block, query)
        block_scores.append((block, score))

    # 3. Keep top 5 most relevant blocks
    relevant_blocks = sorted(block_scores, key=lambda x: x[1], reverse=True)[:5]

    # 4. Search only within those blocks
    results = []
    for block, _ in relevant_blocks:
        block_results = search_within_block(block.id, query, top_k=2)
        results.extend(block_results)

    # 5. Sort all results by score
    results.sort(key=lambda x: x['similarity'], reverse=True)

    return results[:3]
```

EDGE CASES & CHALLENGES
========================

1. LARGE FILES (>50MB)
Problem: Processing takes too long
Solution: Stream processing, show progress bar, async processing

2. SCANNED PDFs (IMAGE-BASED)
Problem: OCR is slow and error-prone
Solution: Detect upfront, warn user, offer manual text paste option

3. TABLES IN PDFS
Problem: Table extraction is unreliable (merged cells, formatting)
Solution: Best effort extraction + fallback to text. v1.0: let user edit extracted tables

4. POOR QUALITY IMAGES
Problem: OCR accuracy <50%
Solution: Preprocessing (sharpen, denoise, deskew) + warn user if confidence is low

5. NON-LATIN SCRIPTS (Arabic, Chinese, etc.)
Problem: Embeddings models may not support well
Solution: v0.1 support PT/EN only. v1.0 add multilingual embeddings

6. KNOWLEDGE CONFLICTS
Problem: Two blocks say different prices for same item
Solution: v0.1 ignore (return both, let LLM handle). v1.0 detect conflicts, alert user

7. OUTDATED KNOWLEDGE
Problem: User uploads new price list, old one still in system
Solution: Version tracking + auto-disable old blocks when new version uploaded

8. HUGE SPREADSHEETS (10k+ rows)
Problem: Can't fit all rows in context
Solution: Filter/search spreadsheet before adding to context (e.g., "show only rows where service=bath")
