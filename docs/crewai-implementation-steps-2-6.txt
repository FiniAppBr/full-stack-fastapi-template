CrewAI Implementation for Knowledge Workflow Steps 2-6
========================================================
Date: 2025-10-28

How CrewAI helps us achieve Steps 2-6 of our knowledge processing pipeline.


==============================================================================
THE PROBLEM (Without CrewAI)
==============================================================================

Manual orchestration is complex:
- Need to coordinate 4 separate AI calls
- Handle dependencies (Step 3 needs output from Steps 1+2)
- Implement parallel execution manually
- Write retry logic for each step
- Track state across steps
- Handle errors gracefully

**With CrewAI: All of this is automatic** ✅


==============================================================================
CREWAI AGENTS = OUR PROCESSING STEPS
==============================================================================

Step 2: Structure Detection → Agent 1 (StructureDetector)
Step 3: Normalization → Agent 2 (DataNormalizer)
Step 4: Conflict Detection → Agent 3 (ConflictChecker)
Step 5: NL Variant Generation → Agent 4 (VariantGenerator)

Each agent has:
- Role (what they do)
- Goal (success criteria)
- Backstory (context for LLM)
- Tools (DeepDiff, PostgreSQL, ftfy, etc.)

IMPLEMENTATION
==============================================================================

```python
from crewai import Agent, Task, Crew, Process
from crewai.tools import tool
from langchain_openai import ChatOpenAI
from pydantic import BaseModel
import instructor
from deepdiff import DeepDiff
import ftfy
from cleantext import clean

# Initialize LLM
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# Initialize Instructor for structured outputs
client = instructor.from_openai(OpenAI())


# ============================================================================
# PYDANTIC MODELS (Structured Outputs)
# ============================================================================

class DocumentStructure(BaseModel):
    doc_type: str  # pricing_table, faq, menu, policy, schedule
    entities: list[str]  # bath, grooming, nail_trim, etc.
    confidence: float

class ConflictReport(BaseModel):
    has_conflicts: bool
    needs_user_input: bool
    conflicts: list[dict]
    details: str
    recommendation: str

class NLVariants(BaseModel):
    variants: list[str]  # 5 natural language versions


# ============================================================================
# TOOLS (Functions agents can use)
# ============================================================================

@tool
def normalize_text(text: str) -> str:
    """Clean and normalize text: fix Unicode, standardize currency, clean whitespace"""
    # Fix Unicode/encoding issues
    text = ftfy.fix_text(text)

    # Clean messy formatting
    text = clean(text, fix_unicode=True, no_urls=False, no_emails=False)

    # Normalize currency: R$ 60,00 → R$60
    import re
    text = re.sub(r'R\$\s*(\d+)[,.]?\d{0,2}', r'R$\1', text)

    # Clean whitespace
    text = ' '.join(text.split())

    return text

@tool
def check_conflicts_with_db(agent_id: str, new_data: dict) -> dict:
    """Query PostgreSQL for existing knowledge blocks and compare with DeepDiff"""
    from app.database import get_session
    from app.models import KnowledgeBlock

    # Fetch existing blocks for this agent
    session = get_session()
    existing_blocks = session.query(KnowledgeBlock).filter(
        KnowledgeBlock.agent_id == agent_id,
        KnowledgeBlock.status == "ready"
    ).all()

    conflicts = []
    for block in existing_blocks:
        # Compare using DeepDiff
        diff = DeepDiff(block.data, new_data, ignore_order=True)

        if diff:
            conflicts.append({
                "block_id": str(block.id),
                "source": block.filename,
                "changes": diff.to_dict()
            })

    return {
        "has_conflicts": len(conflicts) > 0,
        "conflicts": conflicts
    }


# ============================================================================
# STEP 2: STRUCTURE DETECTION AGENT
# ============================================================================

structure_detector = Agent(
    role="Document Structure Analyzer",
    goal="Identify document type and extract key entities with high confidence",
    backstory="""You are an expert at analyzing documents and understanding their
    structure. You can quickly identify if a document is a pricing table, FAQ,
    menu, policy document, or schedule. You also extract relevant entities like
    services, products, or information categories.""",
    llm=llm,
    verbose=True,
    allow_delegation=False
)


# ============================================================================
# STEP 3: NORMALIZATION AGENT
# ============================================================================

normalizer = Agent(
    role="Data Normalizer and Cleaner",
    goal="Clean text, fix encoding issues, standardize formats for consistency",
    backstory="""You are a meticulous data cleaning specialist. You fix broken
    Unicode, standardize currency formatting (especially Brazilian Real), clean
    whitespace, and ensure all text is consistent and searchable.""",
    llm=llm,
    verbose=True,
    tools=[normalize_text],
    allow_delegation=False
)


# ============================================================================
# STEP 4: CONFLICT DETECTION AGENT
# ============================================================================

conflict_checker = Agent(
    role="Conflict Detection Specialist",
    goal="Find contradictions between new and existing knowledge, flag changes",
    backstory="""You are an eagle-eyed analyst who never misses inconsistencies.
    You compare new information with existing knowledge blocks and detect price
    changes, policy updates, or conflicting information. You determine if human
    review is needed.""",
    llm=llm,
    verbose=True,
    tools=[check_conflicts_with_db],
    allow_delegation=False
)


# ============================================================================
# STEP 5: NL VARIANT GENERATOR AGENT
# ============================================================================

variant_generator = Agent(
    role="Natural Language Variant Creator",
    goal="Generate 5 diverse, natural-sounding variants in Brazilian Portuguese",
    backstory="""You are a creative linguist fluent in Brazilian Portuguese.
    You take structured data and generate multiple natural language versions
    that sound conversational and authentic. Your variants help improve search
    accuracy by matching how real customers ask questions.""",
    llm=llm,
    verbose=True,
    allow_delegation=False
)


# ============================================================================
# TASKS (What each agent does)
# ============================================================================

task_detect_structure = Task(
    description="""
    Analyze this document and determine:
    1. Document type: pricing_table, faq, menu, policy, or schedule
    2. Key entities: List all services, products, or topics
    3. Confidence: How confident are you? (0.0 to 1.0)

    Document content:
    {document_content}

    Return JSON matching DocumentStructure schema.
    """,
    agent=structure_detector,
    expected_output="JSON: {doc_type, entities, confidence}"
)

task_normalize = Task(
    description="""
    Clean and normalize this text:
    - Fix any Unicode or encoding issues
    - Standardize currency format (R$ 60,00 → R$60)
    - Clean extra whitespace
    - Ensure consistent formatting

    Text:
    {document_content}

    Use the normalize_text tool.
    """,
    agent=normalizer,
    expected_output="Cleaned, normalized text string"
)

task_check_conflicts = Task(
    description="""
    Check if this new data conflicts with existing knowledge:

    1. Use check_conflicts_with_db tool to query existing blocks for agent_id: {agent_id}
    2. Compare new data structure with existing data
    3. Identify specific conflicts (price changes, policy updates, etc.)
    4. Determine if user input is needed

    New data (normalized):
    {normalized_data}

    Structure info:
    {structure_info}

    Return JSON matching ConflictReport schema.
    """,
    agent=conflict_checker,
    expected_output="JSON: {has_conflicts, needs_user_input, conflicts, details, recommendation}",
    context=[task_detect_structure, task_normalize]  # Waits for these to complete
)

task_generate_variants = Task(
    description="""
    Generate 5 natural language variants in Brazilian Portuguese for this data:

    {normalized_data}

    Examples for "bath for small dog costs R$60":
    - "Banho para cachorro pequeno custa R$60"
    - "Para cães pequenos, o banho sai por R$60"
    - "Quanto é o banho? R$60 para cachorrinho pequeno"
    - "Cachorro pequeno: banho R$60"
    - "O valor do banho para pet pequeno é R$60"

    Make variants sound natural and conversational.
    Return JSON matching NLVariants schema.
    """,
    agent=variant_generator,
    expected_output="JSON: {variants: [5 strings]}",
    context=[task_normalize, task_check_conflicts]  # Waits for clean, conflict-free data
)


# ============================================================================
# CREW (Orchestrates all agents and tasks)
# ============================================================================

knowledge_processing_crew = Crew(
    agents=[structure_detector, normalizer, conflict_checker, variant_generator],
    tasks=[task_detect_structure, task_normalize, task_check_conflicts, task_generate_variants],
    process=Process.sequential,  # Tasks run in order (with automatic parallelization where possible)
    verbose=True,
    memory=False,  # We don't need conversation memory
    cache=True  # Cache LLM responses for similar inputs
)


# ============================================================================
# USAGE
# ============================================================================

def process_document(docling_output: str, agent_id: str) -> dict:
    """
    Process a document through Steps 2-6 using CrewAI

    Args:
        docling_output: Markdown content from Docling extraction
        agent_id: UUID of the agent this knowledge belongs to

    Returns:
        dict with structure, normalized_data, conflicts, variants
    """

    result = knowledge_processing_crew.kickoff(inputs={
        "document_content": docling_output,
        "agent_id": agent_id
    })

    return {
        "structure": result.tasks_output[0].raw,  # Task 1 output
        "normalized_data": result.tasks_output[1].raw,  # Task 2 output
        "conflicts": result.tasks_output[2].raw,  # Task 3 output
        "variants": result.tasks_output[3].raw  # Task 4 output
    }


# Example usage
if __name__ == "__main__":
    docling_markdown = """
    # Pet Grooming Prices

    ## Small Dogs
    - Bath: R$ 60,00
    - Nail trim: R$ 25,00

    ## Large Dogs
    - Bath: R$ 85,00
    - Nail trim: R$ 30,00
    """

    result = process_document(docling_markdown, agent_id="123e4567-e89b-12d3-a456-426614174000")

    print("Structure:", result["structure"])
    print("Normalized:", result["normalized_data"])
    print("Conflicts:", result["conflicts"])
    print("Variants:", result["variants"])
```


==============================================================================
HOW CREWAI HELPS
==============================================================================

✅ **Automatic Orchestration**
   - CrewAI handles task order (sequential with parallelization)
   - Tasks 1+2 run in parallel (no dependencies)
   - Task 3 waits for 1+2 (context parameter)
   - Task 4 waits for 2+3

✅ **Built-in Error Handling**
   - If agent fails, CrewAI retries automatically
   - Verbose mode shows exactly what's happening
   - Easy to debug which step failed

✅ **Tool Integration**
   - Agents use tools (normalize_text, check_conflicts_with_db)
   - No need to manually call functions
   - Agent decides when to use tools based on task

✅ **Context Passing**
   - Task outputs automatically passed to dependent tasks
   - No manual state management
   - Clean separation of concerns

✅ **Structured Outputs**
   - Use Pydantic models for validation
   - Type-safe results
   - Automatic retry if LLM returns invalid JSON

✅ **Performance**
   - Parallel execution where possible
   - Caching for repeated inputs
   - Minimal overhead (8-10 seconds total)

INTEGRATION WITH TEMPORAL (Step 4 Pause)
==============================================================================

```python
from temporalio import workflow, activity
from datetime import timedelta

@activity.defn
async def run_crewai_processing(document: str, agent_id: str) -> dict:
    """Run CrewAI crew as Temporal activity"""
    return process_document(document, agent_id)

@workflow.defn
class KnowledgeWorkflow:

    @workflow.run
    async def run(self, file_id: str):
        # Step 1: Extract with Docling
        document = await workflow.execute_activity(extract_with_docling, file_id)

        # Steps 2-6: CrewAI processing
        result = await workflow.execute_activity(run_crewai_processing, document, self.agent_id)

        # If conflicts need user input, PAUSE
        if result["conflicts"]["needs_user_input"]:
            await workflow.wait_condition(lambda: self.conflicts_resolved, timeout=timedelta(days=7))
            resolution = self.conflict_resolution
        else:
            resolution = None

        # Step 7: Store
        await workflow.execute_activity(store_knowledge, result, resolution)
```
