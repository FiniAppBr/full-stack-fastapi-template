DESIGN PRINCIPLES FOLLOWED
═══════════════════════════════════════════════════════════════════

✅ GOOD PRINCIPLES WE'RE FOLLOWING:

Design:
1. Progressive Disclosure - Start simple (AI chat), reveal complexity only when needed
2. Recognition over Recall - Dropdowns show options, no memorization needed
3. Visibility of System Status - Show metrics, rule triggers, performance
4. User Control & Freedom - Can switch AI↔manual anytime
5. Flexibility & Efficiency - Novice (AI) + expert (manual) paths
6. Consistency - Single source of truth per concept

Code/Architecture:
1. Separation of Concerns - Gating/Validation/Guiding separate engines
2. Open-Closed Principle - Add new actions without changing existing code
3. Configuration over Code - Behavior is JSON data, not hardcoded
4. DRY - Generic UI components work for any field config
5. Single Responsibility - Each engine does ONE thing

Product:
1. Convention over Configuration - Templates + smart defaults
2. Jobs to Be Done - Solves "different behavior for different customers"
3. 80/20 Rule - Templates cover most use cases

⚠️ ANTI-PATTERNS WE'RE AVOIDING:

1. ❌ Dual Interface Confusion - We pick ONE primary (AI), manual is secondary
2. ❌ Complexity Leakage - Hide technical concepts (gating/validation) from users
3. ❌ Paradox of Choice - Reduce paths to value, not multiply them
4. ❌ YAGNI - Don't build what users don't need
5. ❌ Feature Bloat - Focus on core use case first

═══════════════════════════════════════════════════════════════════
CORE INSIGHT
═══════════════════════════════════════════════════════════════════

ConnectAI is a BUSINESS COMMUNICATION PLATFORM where AI agents are one
powerful feature, not the whole product.

The agent doesn't work in isolation - it feeds the whole system:
• Conversations - Shows results of agent work (with smart pills!)
• Contacts - Gets enriched with data agents collect
• Kanban - Gets populated with deals agents create
• Calendar - Books meetings agents schedule
• Analytics - Shows if agent behaviors actually work

This creates a virtuous cycle: better agent → better data → better insights

─────────────────────────────────────────────────────────────────
KEY UX PRINCIPLES FOR AGENT CONFIG:
─────────────────────────────────────────────────────────────────

1. AI CHAT IS PRIMARY
   - Most users never leave the chat
   - Natural language: "make it more casual"
   - AI translates to config: gating_rules, validation_rules, etc.

2. CURRENT SETUP IS SECONDARY
   - Read-only view with quick toggles
   - Expandable sections (progressive disclosure)
   - Shows what's working ("Triggered 3 times today")

3. HIDE TECHNICAL CONCEPTS
   - Users don't see "gating_rules", "validation_rules", "response_schema"
   - They see: "Price Protection", "VIP Treatment", "Customer Tracking"
   - Technical details in "Advanced" section (rarely needed)

4. SHOW IMPACT
   - Every rule shows performance metrics
   - "Blocked 12 prices" proves it's working
   - "83% convert" shows business value

5. BIDIRECTIONAL
   - Can ask AI to change anything
   - Can toggle individual rules on/off
   - Can view generated JSON (for advanced users)

TECHNICAL ARCHITECTURE NOTES
═══════════════════════════════════════════════════════════════════

WHAT'S HARDCODED (MINIMAL):

1. The 3 validation actions in behavior_engines.py:
   • strip_prices
   • block_media
   • append_message

2. The generic UI components (React):
   • Dropdowns
   • Rule builder cards
   • Toggle switches
   • Field editors
   • Chat interface

WHAT'S CONFIGURATION (EVERYTHING ELSE):

• Custom fields → agent.response_schema (JSON in DB)
• Gating rules → agent.gating_rules (JSON in DB)
• Validation rules → agent.validation_rules (JSON in DB)
• Behavior shortcuts → combined configs
• Templates → JSON files shipped with product
• Field display names → stored in response_schema metadata

HOW AI MAKES DECISIONS:

1. AI DECIDES field values organically:
   "This customer's budget is 20k_plus"
   "This lead quality is hot"

2. BUSINESS OWNER DECIDES rules:
   "IF budget is 20k_plus, THEN send premium catalog"
   "IF budget is unknown, THEN hide pricing tags"

3. SYSTEM EXECUTES actions:
   Pre-built functions: send_media(), strip_prices(), exclude_tags()

THE FLOW:

User chats with customer
  ↓
AI classifies: budget_range = "20k_plus"
  ↓
Rules engine checks: IF budget_range == "20k_plus"
  ↓
Rule fires: THEN send premium_collection.pdf
  ↓
Action executes: send_media("premium_collection.pdf")
  ↓
Customer receives catalog
  ↓
Analytics tracks: "VIP Treatment triggered, +1 to counter"

SUMMARY
═══════════════════════════════════════════════════════════════════

ConnectAI is a business communication platform where AI agents are
a powerful feature that feeds data to the entire system:

• Dashboard - See what needs attention
• Conversations - Real messenger with AI assistance + smart pills
• Contacts - Enriched with AI-collected data
• Calendar - Schedule meetings from conversations
• Kanban - Pipeline populated by qualified leads
• Agents - Configure behavior via AI chat (primary) or manual (secondary)
• Analytics - Prove agent behaviors work
• Settings - Account, integrations, team

Key innovation: AI chat for configuration hides complexity while
giving power users full control via expandable sections.

The system follows:
✅ Progressive disclosure
✅ Configuration over code
✅ Single source of truth
✅ Show, don't tell (metrics everywhere)
✅ Flexibility without complexity

And avoids:
❌ Dual interface confusion (AI is primary, manual is view-only)
❌ Feature bloat (focus on core flows)
❌ Technical jargon leaking into UX
❌ Paradox of choice (templates + AI guide users)
