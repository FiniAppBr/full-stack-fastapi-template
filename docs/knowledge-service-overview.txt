Knowledge Service - Executive Overview
=======================================
Date: 2025-10-28 (Updated with CrewAI + final stack decisions)
Audience: Human-readable strategic overview


==============================================================================
THE PROBLEM
==============================================================================

Users need to upload documents (PDFs, Excel, Word, images) so their AI agents
can answer customer questions using that information.

Example: Pet grooming business uploads "pricing.xlsx" → Customer asks "How
much for a small dog bath?" → Agent answers "R$60" (from the file).


==============================================================================
THE SOLUTION - 3 PHASES
==============================================================================

┌─────────────────────────────────────────────────────────┐
│ PHASE 1: UPLOAD (Instant - <500ms)                     │
│                                                         │
│ User uploads file → Save to disk → Return "Processing" │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ PHASE 2: PROCESSING (Background - 8-10 seconds)        │
│                                                         │
│ Step 1: Extract text & tables (Docling)                │
│ Step 2: Detect structure (CrewAI Agent 1) ⚡           │
│ Step 3: Normalize data (CrewAI Agent 2) ⚡             │
│ Step 4: Check conflicts (CrewAI Agent 3) ★             │
│ Step 5: Generate NL variants (CrewAI Agent 4)          │
│ Step 6: Split into chunks & save to database           │
│                                                         │
│ ⚡ = Parallel execution (Steps 2+3 run simultaneously)  │
│ ★ If conflicts → Temporal pauses → User decides        │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ PHASE 3: RETRIEVAL (On Customer Query - <200ms)        │
│                                                         │
│ Customer asks question → Search chunks → Return top 3   │
└─────────────────────────────────────────────────────────┘


==============================================================================
KEY TECHNOLOGY DECISIONS
==============================================================================

1. DOCLING (for document extraction)
   ---------------------------------
   Why: Best accuracy (97.9% for tables), fastest CPU performance,
        handles all file types (PDF, Office, images)
   Replaces: pypdf, python-docx, unstructured.io
   Cost: FREE (open source)

2. CREWAI (for agent orchestration - Steps 2-5)
   ----------------------------------------------
   Why: Role-based agents, parallel execution, lightweight
   Agents: StructureDetector, DataNormalizer, ConflictChecker, VariantGenerator
   Cost: FREE (open source, MIT license)
   Stars: ⭐ 39.8k (most popular multi-agent framework)

3. TEMPORAL (for workflow orchestration + Step 4 pause)
   -----------------------------------------------------
   Why: Pause/resume for conflict resolution (can wait hours/days),
        automatic retries, built-in monitoring UI
   Replaces: RQ/Celery (can't pause workflows)
   Cost: FREE (self-hosted)
   Already installed: ✅ (temporalio in dependencies)

4. POSTGRESQL + PGVECTOR (for storage & search)
   ----------------------------------------------
   Why: Unified storage, supports both keyword and semantic search
   Cost: FREE

5. INSTRUCTOR + PYDANTIC (for structured outputs)
   ------------------------------------------------
   Why: Type-safe AI responses, automatic validation, retries
   Stars: ⭐ 11.7k + 25.6k (industry standard)
   Cost: FREE (libraries) + GPT-4o-mini calls ($0.0006/file)

6. DEEPDIFF + ftfy + clean-text (for conflict detection & normalization)
   ----------------------------------------------------------------------
   Why: DeepDiff compares data, ftfy fixes Unicode, clean-text standardizes
   Stars: ⭐ 2.4k + 4.0k + 997
   Cost: FREE

7. COHERE EMBEDDINGS (for semantic search - Phase 3)
   --------------------------------------------------
   Why: Best for Portuguese, 5x cheaper than OpenAI
   Cost: $0.0001 per query


==============================================================================
WHY CREWAI + TEMPORAL? (vs manual orchestration)
==============================================================================

Problem: We have 4 AI processing steps that need coordination, and Step 4
         might need to pause for hours/days waiting for user input.

Manual Orchestration:
  ❌ Complex coordination code
  ❌ Manual parallelization logic
  ❌ Can't pause and resume
  ❌ Hard to debug
  ❌ Manual error handling

CrewAI (for Steps 2-5):
  ✅ 4 agents = 4 steps (natural fit)
  ✅ Automatic parallel execution (Steps 2+3 run simultaneously)
  ✅ Role-based design (easy to understand)
  ✅ Built-in error handling and retries
  ✅ Fast (8-10 seconds vs 13-20 manual)
  ✅ Clean, maintainable code

Temporal (wrapper around CrewAI):
  ✅ Pause workflow if conflicts need user input
  ✅ Full execution history
  ✅ Monitoring UI (localhost:8233)
  ✅ Durable execution (survives crashes)

Decision: Hybrid approach - CrewAI for fast agent processing,
          Temporal for pause/resume orchestration


==============================================================================
THE 6 PROCESSING STEPS (Explained)
==============================================================================

Step 1: EXTRACTION
   What: Get text and tables from file
   Tool: Docling
   Time: 3-5 seconds
   Cost: FREE

Step 2: STRUCTURE DETECTION (CrewAI Agent 1)
   What: Understand what kind of document (pricing table? FAQ? menu?)
   Tool: Instructor + GPT-4o-mini + Pydantic
   Time: 2-3 seconds (runs parallel with Step 3)
   Cost: $0.0001

Step 3: NORMALIZATION (CrewAI Agent 2)
   What: Clean text, fix Unicode, standardize formats
   Tool: ftfy + clean-text + custom regex
   Time: <1 second (runs parallel with Step 2)
   Cost: FREE (no LLM needed)

Step 4: CONFLICT DETECTION ★ CRITICAL ★ (CrewAI Agent 3)
   What: Compare with existing knowledge, find contradictions
   Example: "Old file says R$55, new file says R$60 - which is correct?"
   Tool: DeepDiff + Instructor + PostgreSQL queries
   Time: 2-3 seconds
   Cost: $0.0002
   Special: If conflicts → Temporal PAUSES workflow → User decides

Step 5: NL VARIANT GENERATION (CrewAI Agent 4)
   What: Generate 5 natural language versions of data
   Example: {"service": "bath", "price": 60} →
            ["Banho custa R$60", "Para cachorro pequeno, o banho sai R$60", ...]
   Why: Better search matching (20-30% accuracy improvement)
   Tool: Instructor + GPT-4o-mini
   Time: 2-3 seconds
   Cost: $0.0003

Step 6: STORAGE
   What: Split into chunks, save to PostgreSQL, generate embeddings (v0.3+)
   Tool: Docling HierarchicalChunker + PostgreSQL + pgvector
   Time: 1-2 seconds
   Cost: FREE

TOTAL TIME: 8-10 seconds (faster due to parallel execution!)
TOTAL COST: ~$0.0006 per file (~R$0.003)

NOTE: Validation step removed - Pydantic validates in Step 2, normalization
      cleans data in Step 3, conflicts catch issues in Step 4. No need for
      separate validation step.


==============================================================================
SEARCH STRATEGIES (3 Versions)
==============================================================================

v0.1: KEYWORD SEARCH (Week 1)
   How: PostgreSQL full-text search
   Speed: ~200ms
   Accuracy: ~70%
   Pros: Zero setup, fast, good enough to start
   Cons: "haircut" won't match "men's cut"

v0.3: SEMANTIC SEARCH (Week 3)
   How: Vector embeddings + pgvector
   Speed: ~50ms
   Accuracy: ~85%
   Pros: Understands meaning, better matches
   Cons: Requires embedding generation (slower processing)

v1.0: HYBRID SEARCH (Week 5+)
   How: 70% semantic + 30% keyword
   Speed: ~20ms (with caching)
   Accuracy: ~90%
   Pros: Best of both worlds
   Cons: Most complex

Decision: Start with v0.1, upgrade if accuracy <70%


==============================================================================
DATABASE STRUCTURE
==============================================================================

EXISTING TABLE (blocks):
   Add columns:
   - status (ready/processing/failed/needs_review)
   - file_size
   - markdown_content
   - processing_error

NEW TABLE (knowledge_chunks):
   - id
   - block_id (link to blocks table)
   - chunk_index (position in document)
   - chunk_type (paragraph/table/heading)
   - content (the actual text)
   - page_number
   - embedding (for semantic search - Phase 3)
   - metadata (JSON)
   - times_retrieved (analytics)
   - positive_feedback (analytics)
   - negative_feedback (analytics)

Why chunks? So we can search smaller pieces instead of entire documents.
Better accuracy, less noise.

==============================================================================
CONFLICT DETECTION (Why It's Critical)
==============================================================================

THE PROBLEM:
   User uploads "pricing_old.pdf" → Bath: R$55
   Later uploads "pricing_new.xlsx" → Bath: R$60

   Without conflict detection:
   Customer asks "How much is bath?"
   Agent might say "Between R$55-60" ← WRONG! Confusing!

THE SOLUTION:
   Step 4 of processing detects conflict:

   1. Micro-agent compares new file vs existing files
   2. Finds: "Price changed R$55 → R$60"
   3. Pauses Temporal workflow
   4. Notifies user: "Conflict detected - which price is correct?"
   5. User clicks "Replace old pricing"
   6. Temporal workflow resumes
   7. Marks old file as "superseded"
   8. Only new pricing is used

Result: Agent never contradicts itself!

==============================================================================
RISKS & MITIGATION
==============================================================================

Risk 1: Search accuracy <70% (agent can't find answers)
   Impact: Users lose trust, churn
   Mitigation: Test with 20 real questions per business type in Week 1
   Contingency: Add semantic search (Phase 3) if accuracy low

Risk 2: Docling crashes on large files
   Impact: Processing fails, bad user experience
   Mitigation: 50MB file limit, 10-minute timeout, graceful error handling
   Contingency: Retry up to 3 times, notify user if all fail

Risk 3: Temporal workflow stuck
   Impact: File never finishes processing
   Mitigation: Built-in timeouts, monitoring, automatic retries
   Contingency: Manual workflow restart via Temporal UI

Risk 4: Memory exhaustion (16GB VPS)
   Impact: Server crashes
   Mitigation: Process one file at a time, clear memory after each
   Monitoring: Track RAM usage, alert if >80%
