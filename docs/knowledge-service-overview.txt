==============================================================================
THE PROBLEM (UNCHANGED)
==============================================================================

Users need to upload documents (PDFs, Excel, Word, images) so their AI agents
can answer customer questions using that information.

Example: Pet grooming business uploads "pricing.xlsx" → Customer asks "How
much for a small dog bath?" → Agent answers "R$60" (from the file).

Currently: Knowledge must be manually entered via API or seeding script.

DATABASE SCHEMA (Current)
==============================================================================

TABLE: knowledge_base (Working)
--------------------------------
id              INTEGER PRIMARY KEY
content         VARCHAR (the actual text)
category        VARCHAR (pricing/service/hours/policy/product/faq)
agent_id        VARCHAR (which business/agent)
title           VARCHAR (short display name)
metadata_json   VARCHAR (optional JSON data)
embedding       VECTOR(1024) (Voyage AI embedding)
created_at      TIMESTAMP
updated_at      TIMESTAMP
is_active       BOOLEAN (soft delete flag)

Indexes:
- Primary key on id
- Vector index for cosine similarity search


TABLE: blocks (Working)
-----------------------
id                      INTEGER PRIMARY KEY
agent_id                INTEGER (foreign key to agent.id)
block_type              VARCHAR (knowledge/personality/action)
name                    VARCHAR
description             VARCHAR
is_active               BOOLEAN
created_at              TIMESTAMP
updated_at              TIMESTAMP

# Knowledge block fields
content                 VARCHAR
content_type            VARCHAR
file_path               VARCHAR (future: path to uploaded file)
file_type               VARCHAR (future: pdf/docx/xlsx)

# Personality block fields
tone                    VARCHAR
languages               VARCHAR
use_emojis              BOOLEAN
emoji_frequency         VARCHAR
response_length         VARCHAR
constraints             VARCHAR
guidelines              VARCHAR
example_conversations   JSON

# Action block fields
action_type             VARCHAR
config                  JSON
integration_id          INTEGER
trigger_conditions      VARCHAR
requires_confirmation   BOOLEAN

# Shared
metadata_               JSON (flexible for any block type)

==============================================================================
KEY DECISIONS & RATIONALE
==============================================================================

1. Voyage AI over OpenAI Embeddings
   Why: Better Portuguese support, 5x cheaper, same quality
   Cost: $0.00001 per query vs $0.00005 (OpenAI)

2. pgvector over Pinecone/Weaviate
   Why: Simpler stack, no external service, faster queries
   Cost: FREE vs $70-100/month

3. Manual entry for MVP (current)
   Why: Validate semantic search works before building upload pipeline
   Result: 85%+ accuracy proven → ready for Phase 1

4. Skipping CrewAI for initial upload (planned change)
   Why: Get value faster, add complexity only if needed
   Approach: Basic Docling extraction → chunks → embeddings → done

5. Mem0 token estimation over API tracking
   Why: Mem0 doesn't expose usage, estimation 99.9% accurate
   Result: Complete visibility into all token usage

6. Single knowledge_base table (current)
   Why: Simpler for manual entry, good enough for 100s of chunks
   Future: Add knowledge_chunks table when file upload adds 1000s


==============================================================================
RISKS & MITIGATION
==============================================================================

Risk 1: Docling fails on complex PDFs
   Impact: Processing fails, bad UX
   Mitigation: 50MB limit, 10-min timeout, graceful error handling
   Contingency: Retry 3x, notify user, allow manual entry

Risk 2: Duplicate knowledge from multiple uploads
   Impact: Agent gives redundant answers
   Mitigation: (Phase 2) Conflict detection via CrewAI
   Current: Manual deduplication by user

Risk 3: Poor chunking strategy
   Impact: Relevant info split across chunks, accuracy drops
   Mitigation: Test multiple strategies (paragraph, fixed-size, semantic)
   Fallback: Larger chunks (more tokens but better context)

Risk 4: Memory exhaustion (16GB VPS)
   Impact: Server crashes during processing
   Mitigation: Process one file at time, clear memory after
   Monitoring: Alert if RAM >80%
