CONTEXT MANAGEMENT STRATEGY - ConnectAI Assistant
=================================================

CURRENT TOKEN USAGE (Per Conversation)
---------------------------------------

Component                    | Tokens | Cost
---------------------------- | ------ | -----
Intent classification        | 170    | $0.000026 (UNUSED - just stored in logs)
RAG embedding + retrieval    | 250    | $0.000038
Response generation          | 700    | $0.000105
Memory save (Mem0)           | 831    | $0.000125 (EVERY turn)
Conversation history (DB)    | FREE   | $0

TOTAL: ~1,956 tokens/conversation = $0.000354/conversation

PROBLEMS:
1. Mem0 saves after EVERY turn (831 tokens × every message) - wasteful
2. Intent classification (170 tokens) not used for any logic - just metadata
   - No routing, no handoff triggers, no behavior changes
   - Real-world use cases need: sentiment, handoff triggers, urgency
   - Intent ("question", "booking") is wrong abstraction


KEY INSIGHTS (Research-Backed 2025)
------------------------------------

1. RAG vs Context Stuffing
   - 40K doc, 200 convos/day: RAG = $0.27/month, stuffing = $36/month (106x cheaper)
   - Keep using RAG for all knowledge bases

2. Memory Extraction Timing
   - Mem0 default: Save after every turn
   - Research: End-of-session + periodic extraction is better
   - Conversation patterns: 70% are 1-3 turns (no memory value)
   - Hybrid approach: End-of-conv + turn threshold = 80% savings

3. Intent Classification is Wrong Abstraction
   - Real-world handoff triggers: sentiment (angry), complexity, emergencies, out-of-scope
   - NOT intent categories like "question" or "booking"
   - Businesses need actionable flags: requires_handoff, urgency, sentiment
   - Dedicated classifier = 170 tokens wasted on unused metadata

4. Output Tokens Cost 4x Input
   - $0.60 vs $0.15 per 1M tokens
   - Response length control = high ROI

## Smart Memory Triggers

### End-of-Conversation Trigger
- Save memory ONCE per conversation (not every turn)
- Trigger: 3+ min inactivity OR explicit end signal
- Client-side timeout (simplest):

```javascript
// frontend: agent-test-chat.jsx
let inactivityTimer = null;
const TIMEOUT = 3 * 60 * 1000; // 3 min

function resetTimer(conversationId) {
  clearTimeout(inactivityTimer);
  inactivityTimer = setTimeout(() => {
    fetch(`/api/v1/conversations/${conversationId}/end`, { method: 'POST' });
  }, TIMEOUT);
}
```

```python
# backend: new endpoint
@router.post("/conversations/{conversation_id}/end")
async def end_conversation(conversation_id: str):
    logs = get_conversation_logs(conversation_id)
    if len(logs) >= 2:  # At least 2 turns
        messages = format_for_mem0(logs)
        await save_conversation_memory(user_id, messages, metadata)
```

Savings: ~665 tokens/conversation (80% of memory cost)

### Turn Threshold Fallback
- Also save after 10 turns (for long conversations)
- Prevents memory buffer overflow

```python
# In workflow
if len(self.conversation_buffer) >= 20:  # 10 turns
    await workflow.execute_activity(save_conversation_memory, ...)
    self.conversation_buffer = self.conversation_buffer[-10:]
```

### Agent-Flagged Urgent Memories (Optional)
- Response agent flags "memory_worthy": true for critical info
- Example: allergies, complaints, preferences
- Saves immediately (rare, high-value only)

### Increase History Window
- Change from 3 turns → 10 turns (FREE, just DB query)
- Compensates for less frequent memory saves

Expected savings: ~665 tokens/conversation (34% reduction)

## Remove Intent + Add Structured Output

### Remove Intent Classification Agent
- Delete dedicated intent classifier (170 tokens)
- Not used for routing/logic, just stored as metadata
- Replace with actionable structured output

### Add Structured Output for Handoff Logic
- Response agent outputs actionable flags using OpenAI Agents SDK
- Based on real-world use cases: sentiment, handoff triggers, urgency

```python

    response_format={
```

### Function Tools
Turn Python functions into tools the agent can call automatically.
**Use cases:** Booking, payments, database queries, API calls

Example: Calendar booking integration
```python
def check_availability(date: str, time: str, service: str) -> dict:
    """Check appointment availability in calendar"""
    # Integration with Google Calendar, Calendly, etc
    slots = calendar_api.get_available_slots(date, service)
    return {"available": True, "slots": slots}

def book_appointment(customer_id: str, date: str, time: str, service: str) -> dict:
    """Book appointment for customer"""
    booking_id = calendar_api.create_booking(customer_id, date, time, service)
    send_confirmation_sms(customer_id, booking_id)
    return {"booking_id": booking_id, "confirmed": True}

def send_payment_link(customer_id: str, amount: float, description: str) -> dict:
    """Generate and send payment link (Stripe, Mercado Pago, etc)"""
    link = payment_processor.create_link(amount, description)
    whatsapp_api.send_message(customer_id, f"Payment link: {link}")
    return {"payment_link": link, "sent": True}

# Agent automatically calls these functions when needed
agent = Agent(
    name="Assistant",
    tools=[check_availability, book_appointment, send_payment_link]
)
```

**Benefits:**
- Agent can DO things, not just talk
- Automatic schema generation from function signatures
- Pydantic validation built-in
- Real business actions (booking, payments)

```python
# AI agent with handoff capability

    name="AI Assistant",
```

### Sessions
Automatic conversation history management - replace manual DB queries.
**Use cases:** Cleaner code, automatic persistence, handoff support

Example: Current vs Sessions
```python
# CURRENT (manual)
conversation_history = await workflow.execute_activity(
    get_conversation_history,
    args=[customer_id, agent_id, 3]
)
history_context = format_history(conversation_history)
agent = Agent(instructions=f"... {history_context} ...")

# WITH SESSIONS (automatic)
session = SQLiteSession(f"conv_{customer_id}_{agent_id}")
result = await Runner.run(agent, input.message, session=session)
# History automatically included, no manual queries
```

**Session storage options:**
- `SQLiteSession`: File-based, good for MVP
- `SQLAlchemySession`: Use existing PostgreSQL database
- `OpenAIConversationsSession`: OpenAI-hosted (privacy concerns)

**Recommended: SQLAlchemySession**
```python
from agents import SQLAlchemySession
from app.core.config import settings

# Use existing PostgreSQL database
session = SQLAlchemySession(
    connection_string=str(settings.SQLALCHEMY_DATABASE_URI),
    session_id=f"conv_{customer_id}_{agent_id}"
)

# First turn
result = await Runner.run(agent, "What are your hours?", session=session)

# Second turn - automatic history
result = await Runner.run(agent, "And on weekends?", session=session)

# Access history if needed
history = session.get_items()

# Clear session when conversation ends
if inactive_for_3_minutes:
    session.clear_session()
```

**Benefits:**
- No manual history queries
- No manual formatting
- Works with handoffs (next agent sees full history)
- Cleaner workflow code

**Implementation:**
1. Replace `get_conversation_history` activity with Sessions
2. Migrate to SQLAlchemySession (use existing PostgreSQL)
3. Update workflow to use session-based runs
4. Remove manual history formatting code
5. Test history persistence across turns

Savings: Reduces code complexity, potentially ~50 lines of workflow code
