Minimals Demo Content - Cleanup Plan
=====================================

CURRENT SITUATION
-----------------
- Minimals template has ~20 demo pages (User, Product, Order, Invoice, Blog, Job, Tour, etc.)
- These are valuable references for building our own pages
- Taking up space in navigation sidebar
- May confuse users during development

OPTIONS
-------

Option 1: Hide from Navigation (Keep Files) ★ RECOMMENDED
----------------------------------------------------------
Pros:
+ Files remain accessible for reference
+ Easy to copy patterns when building new pages
+ Can still access via direct URL if needed
+ No risk of breaking imports
+ Fastest implementation (1 line change)

Cons:
- Files still in codebase taking up space
- Can't easily browse them in sidebar

Implementation:
```javascript
// config-nav-dashboard.jsx
export const navData = [
  // ... our sections ...

  // Comment out or remove this entire section:
  // {
  //   subheader: 'Minimals Demo',
  //   items: [ ... ]
  // },
];
```

How to reference later:
- Direct URL: http://localhost:5459/dashboard/user/list
- File reference: /opt/connectai/frontend/src/pages/dashboard/user/list.jsx
- Copy patterns from sections folder


Option 2: Move to Archive Branch
---------------------------------
Pros:
+ Clean main codebase
+ Still accessible via git
+ Proper separation of demo vs production code

Cons:
- Harder to reference (need to switch branches)
- More complex git workflow
- Need to create archive branch

Implementation:
1. Create branch: git checkout -b minimals-demo-archive
2. Keep all demo code in that branch
3. Switch back to main: git checkout main
4. Remove demo pages from main
5. Reference via: git show minimals-demo-archive:path/to/file


Option 3: Move to /archive Folder
----------------------------------
Pros:
+ Files still in repo for reference
+ Clear separation
+ Easy to browse and copy from

Cons:
- Need to update imports if we want to use them
- Takes up repo space
- Need to gitignore or commit

Implementation:
1. Move demo pages: mv frontend/src/pages/dashboard/user frontend/archive/minimals-pages/user
2. Keep for reference
3. Update .gitignore if needed


Option 4: Complete Removal
---------------------------
Pros:
+ Cleanest codebase
+ Smallest bundle size
+ Forces us to build from scratch

Cons:
- Lose valuable reference code
- Harder to learn Minimals patterns
- Need to reference GitHub/docs instead

Implementation:
1. Remove all demo pages
2. Remove unused sections
3. Keep only what we use

NOT RECOMMENDED - we're still learning Minimals
